# Система учёта и документооборота ЛНК — техническое задание

Архитектура: Excel + VBA, мастер-ПК, обмен через сеть/флешку.
Статус: **реализовано, версия 1.7** — см. `ИЗМЕНЕНИЯ.md` за тем, что сделано, и раздел 20.2
здесь за тем, что ещё нужно от вас.

Ветка Access закрыта окончательно — у сотрудников нет опыта работы с ним, порог входа
выше пользы. Материалы по ней (схема, макросы, импорт CSV) удалены из проекта, не только
из документов.

---

## 1. Что решаем

Три рабочих места сейчас, с расчётом на расширение до шести. У каждого полный
комплект локально, в общей папке — только обмен. Добавление рабочего места — это
установка книги и присвоение кода (раздел 3.2), переделывать ничего не надо.
Сеть есть, но ненадёжная, поэтому всё должно продолжать работать без неё, а обмен —
уметь идти и через флешку без изменений в коде.

Требования, зафиксированные по ходу обсуждения:

| Требование | Как закрывается |
|---|---|
| Основные файлы на каждом рабочем месте | Локальные `.xlsm` + `.xlsx`, сеть не нужна для работы |
| В сети минимум | Счётчики, дельты, свод, версия — сотни килобайт |
| Обновление через сеть или флешку | Один механизм, отличается только корневой путь |
| Номера строго без пропусков | Единый счётчик + разделение «черновик / регистрация» |
| Актуальность в течение минут | Автосинхронизация по таймеру + при открытии/закрытии |
| Справочники правит каждый | Построчный обмен, слияние у мастера, отчёт о конфликтах |
| Учёт «кто где» | Отдельный реестр отсутствий + связь с планированием |
| Паспорт ЛНК из реестров | Сборка по кнопке, 6 разделов из 11 — прямые выгрузки (раздел 10) |
| Графики обслуживания оборудования | Реестр обслуживания + расчёт плана из периодичности (раздел 11) |
| Журнал выдачи оборудования | Реестр выдач со связью с «СИ» и проверками (раздел 12) |
| Печать журналов в конце года | Общий механизм для всех журналов (раздел 14) |

## 2. Состав файлов

### На каждом рабочем месте (локально)

```
D:\ЛНК\
├── ЛНК_Программа.xlsm     ← код, макросы, пульт, печатные формы
├── ЛНК_Данные.xlsx        ← журнал, справочники, кто-где, задачи
├── Шаблоны\               ← 8 шаблонов Word (#Плейсхолдеры)
├── Готовые\               ← сформированные акты и протоколы, по годам и методам
├── Копии\                 ← локальные копии данных, 30 дней + помесячно (16.2)
├── Обмен_зеркало\         ← только у мастера: копия общей папки (16.5)
└── Версии\                ← предыдущие версии программы для отката (15.1)
```

**Программа и данные разделены намеренно.** Обновление версии заменяет только
`ЛНК_Программа.xlsm`; `ЛНК_Данные.xlsx` не трогается никогда. Иначе любое обновление
затирало бы рабочие данные — это самая частая причина, по которой такие системы
перестают обновлять.

### В общей папке (сеть или флешка)

```
\\сервер\ЛНК_Обмен\   (или E:\ЛНК_Обмен\)
├── Счётчики\
│   ├── ВИК-2026.txt          ← одно число
│   ├── УЗТ-2026.txt
│   └── … по методу на каждый год
├── Входящие\
│   └── 20260901-1432-Матяш.csv    ← дельты от специалистов
├── Свод\
│   └── ЛНК_Свод.xlsx              ← публикует мастер
├── Обработанные\
│   └── 2026-09\                   ← применённые дельты, не удаляются (16.4)
├── Конфликты\
│   └── Конфликты_20260901.csv     ← спорные правки для разбора
└── Версия\
    ├── версия.txt                 ← номер, дата, кто выпустил, контрольная сумма
    ├── носители.txt               ← серийные номера разрешённых флешек (15.2)
    └── ЛНК_Программа.xlsm
```

Внутри `Свод\` рядом с `ЛНК_Свод.xlsx` лежит `История\` — состояния свода перед каждой
сборкой (16.3), и `мастер.txt` — кто сейчас мастер (3.1).

Путь к общей папке — **настройка в книге, а не константа в коде**. Нет сети — макрос
предлагает выбрать путь к флешке, дальше всё работает так же.

## 3. Роли, коды рабочих мест, мастер

### 3.1. Роли

- **Специалист** (любое рабочее место): вводит данные, формирует документы, отправляет
  дельты, получает свод.
- **Мастер** (одно рабочее место в каждый момент): дополнительно собирает дельты,
  разрешает конфликты, публикует свод.

Роль мастера — **переключаемая галочка в настройках книги**, не привязана к человеку.
Мастером может быть любой сотрудник и любое рабочее место, ничего специального на нём
не установлено — та же самая книга, та же самая кнопка.

Чтобы не вышло «мастера сегодня нет, и никто не собрал свод», в общей папке лежит файл
`Свод\мастер.txt`: код рабочего места, ФИО, дата назначения. При запуске книга его
читает и показывает в шапке Меню: «Мастер сегодня — Иванов (ПК3)». Кнопка «Взять роль
мастера на себя» перезаписывает этот файл и снимает роль с прежнего — двух мастеров
одновременно не бывает.

Если тот, кто числится мастером, отсутствует по реестру «Кто где», книга при запуске
у остальных пишет прямо: «Мастер (Иванов) в отпуске до 14.09. Свод последний раз
собирался 01.09. Взять роль на себя?». Никакой договорённости заранее не требуется.

Это цена варианта «мастер-ПК»: логика слияния пишется один раз вместо шести, но пока
мастер не собрал свод, остальные видят данные на момент последнего свода.

### 3.2. Коды рабочих мест — что это и зачем

Это **внутренний технический признак, который никогда не печатается ни в одном
документе**. Он не имеет отношения к регистрационному номеру `204-2026-ВИК` — тот
выдаётся счётчиком централизованно и идёт без пропусков (раздел 5).

Зачем он нужен. Каждое рабочее место работает автономно и заводит записи, не спрашивая
разрешения у сети. Если запись помечать просто порядковым числом, то два человека,
создавшие в один день по записи на разных ПК, оба получат «запись № 148», и при
слиянии у мастера одна затрёт другую. Поэтому во внутренний идентификатор записи
подставляется код того рабочего места, где она создана:

| Код | Идентификатор записи | Смысл |
|---|---|---|
| ПК1 | `ПК1-2026-0147` | 147-я запись, созданная на первом рабочем месте в 2026 году |
| ПК3 | `ПК3-2026-0147` | 147-я запись на третьем — с первой не конфликтует |

**Код привязан к компьютеру, а не к человеку.** Это важно: сотрудник может сегодня
сесть за другой ПК, на одном месте могут работать посменно двое. Локальный счётчик
записей живёт в файле данных на конкретной машине, поэтому и код должен обозначать
машину. Кто именно внёс запись, хранится отдельным полем «Кем внесено» — по ФИО из
справочника специалистов.

**Предложение:** коды `ПК1` … `ПК6` (с запасом до `ПК9` — расширение до шести человек
и дальше ничего не ломает). Никакого списка заранее согласовывать не нужно: код
задаётся один раз при установке на машину, в настройках книги. От вас требуется
только решить, по какому принципу их раздать — по номеру кабинета, по инвентарному
номеру ПК или просто по порядку. Проще всего по порядку.

Две защиты от ошибки установки:
- книга не даёт вводить данные, пока код рабочего места не заполнен;
- мастер при сборке свода проверяет, что два разных ПК не прислали дельты с одним
  кодом, и выводит это в отчёт о конфликтах. Если при развёртывании файл скопировали
  с машины на машину вместе с настройками — это вскроется в первый же день, а не
  через полгода потерянной записью.

## 4. Модель данных

### 4.1. Журнал — в вашем формате (одна строка = один объект контроля)

Возвращаемся к структуре, которая у вас уже работает: строка описывает **один объект
за одну дату**, применённые методы — колонками. Отдельные журналы по методам строятся
из этого листа для печати.

| Группа | Поля |
|---|---|
| Служебное | `ID записи` (например `ПК1-2026-0147`: код рабочего места + год + счётчик, раздел 3.2 — в документах не печатается), `Статус` (Черновик / Зарегистрирован), `Кем внесено`, `Изменено` |
| Акт | **№ акта** — своя серия номеров (`АКТ 01-2026`). Один акт охватывает несколько строк: у каждого объекта внутри акта свои номера протоколов по методам |
| Общее | № п/п, Дата проведения контроля, Заказывающее подразделение |
| Объект | `ID объекта` (ссылка на справочник, раздел 4.5), **Наименование в документе** (что печатается — редактируется), Заводской / рег. № объекта |
| Учёт экземпляров | № экз. и дата передачи в архив ЛНК, № экз. / исходящий номер / дата отправки, Отправитель |
| По каждому методу (×8) | `<Метод>: №`, `<Метод>: исполнитель` — для ВИК, УЗД, УЗТ, АЭ, ТВ, ТК, ВД, МК |
| Прочее | Примечание |

Метод, который не применялся, остаётся пустым. Колонка исполнителя — выбор из
справочника специалистов, не свободный текст. Объект — выбор из справочника объектов;
печатаемое наименование при этом остаётся редактируемым (раздел 4.5).

**Акт — отдельный уровень учёта, и его чуть не потеряли.** В первой редакции ТЗ
строка журнала описывала объект, а акта не было вовсе. Разбор вашего исходного
журнала показал, что уровня два: акт один на работу и охватывает несколько
объектов (в 2026 году — 64 акта на 315 строк, самый крупный из 36 объектов), а у
каждого объекта внутри акта свои номера протоколов по методам.

Отсюда следствия: у актов **своя серия номеров** и свой счётчик, а **пакет
документов собирается по акту целиком** — протоколы по всем его объектам, а не по
одной строке. Номер акта присваивается кнопкой сразу выделенным строкам: именно
на ручном вписывании акты и дублируются.

Работа без акта допускается: 49 строк из 315 в исходном журнале идут без него —
это случаи, когда выпускался только протокол по одному методу. Тогда пакет
печатается по одной строке.

**Печатные журналы по методам.** Листы `Печать_ВИК`, `Печать_УЗТ` и т.д. **строятся
макросом заново** из основного листа, а не тянутся формулами ИНДЕКС/ПОИСКПОЗ.
Причина прямая: в вашем текущем файле такие формулы протянуты на 2000 строк, а в
колонке-подписи до сих пор стоит «2025» вместо «2026» — формулы этого не замечают,
потому что ищут по другому полю. Перестроение макросом убирает целый класс таких
ошибок и работает быстрее.

Состав печатного журнала: № п/п, регистрационный номер (`№-Год-Метод`), дата
регистрации, заказывающее подразделение, объект контроля (с заводским номером),
исполнитель, № экз. и дата в архив, № экз. / исходящий / дата отправки, отправитель,
примечание. Титульный лист — по вашему образцу, с учётным номером журнала.

### 4.2. Справочники

`СИ`, `Специалисты`, `НД`, `Инструктажи` — как в собранной книге v2, плюс **обязательное
поле `ID`** у каждой записи (`СИ-0012`, `СП-0003`). Без стабильного ID построчное
слияние невозможно: номер строки меняется, заводской номер могут поправить при
опечатке, ФИО пишут по-разному.

Правит любой сотрудник. Конфликты разбираются у мастера (раздел 6).

Состав полей расширяется под сборку Паспорта — реестры должны содержать всё, что
требует его форма, иначе документ соберётся с пробелами. Перечень дополнительных
полей для «СИ» и «Специалистов» — в разделе 10.3.

### 4.3. Кто где — новый реестр

| Поле | Содержание |
|---|---|
| ID | `КГ-0031` |
| ФИО | из справочника специалистов |
| Вид | Отпуск / Больничный / Командировка / Выезд на измерения / Прочее |
| Дата с, Дата по | период |
| Основание | № приказа, ссылка на график отпусков |
| Доступен для работ | Да / Нет — подставляется по виду, можно переопределить вручную |
| Кем внесено, Изменено | автоматически |

Важное различие: **«выезд на измерения» — это не отсутствие**, человек работает.
Для планирования он занят, но документ по его работе оформлять можно. Поэтому вид
отсутствия и признак «доступен» разведены отдельными полями.

Список видов намеренно короткий: пять пунктов выбираются из выпадающего списка
быстрее, чем восемь, а всё нетиповое (учёба, отгул, отпуск без сохранения) вносится
как «Прочее» с пояснением в поле «Основание». Если какой-то вид начнёт встречаться
часто, он добавляется в список одной правкой справочника — переделывать ничего не
придётся.

Отдельный лист **«График отпусков»** — плановый, на год: ФИО и периоды. По кнопке из
него создаются записи в «Кто где», чтобы не вносить одно и то же дважды.

### 4.4. Задачи и План-график

Без изменений относительно собранной книги v2, добавляется только проверка занятости
исполнителя (раздел 8).

### 4.4а. Замеры и данные протоколов

Первая редакция ТЗ этого не предусматривала: документы формировались с шапкой,
а результаты замеров дописывались в Word руками. Это дыра — в шаблоне УЗТ 24
поля под точки, в ТВ 16.

**Три уровня данных, и каждый живёт там, где меняется:**

| Что | Где | Как часто меняется |
|---|---|---|
| Паспорт объекта: материал, толщины, давления, среда | Справочник объектов | раз на объект |
| Заключение, дефекты, НД, средства НК, руководитель | Лист «Данные протоколов», строка на «запись + метод» | раз на работу |
| Точки замеров | Лист «Замеры», строка на точку | каждый контроль |

Паспортные поля названы точно так же, как плейсхолдеры шаблонов, и
подставляются по имени: «Марка материала» → `#Марка_материала`. Таблицы
соответствия нет намеренно — её пришлось бы править при каждом новом поле.
Новую колонку достаточно назвать как плейсхолдер, и она начнёт подставляться.

**Переопределение.** Если по конкретной работе паспортное значение другое, оно
пишется в «Переопределения паспорта» как `Поле=Значение` и действует только на
этот документ. Справочник остаётся историей объекта: правка задним числом
изменила бы смысл прошлогодних протоколов.

**Аппаратурные настройки АЭ — свой лист.** Двенадцать полей про настройку
аппаратуры и режим нагружения не описывают ни объект, ни результат, и у
остальных методов пустуют. Они копируются из прошлой работы по АЭ, потому что
меняются мало, а переписывать двенадцать полей руками — верный способ ошибиться
в одном из них. Уже заполненное при копировании не затирается.

**Замеры — пока по УЗТ и ТВ.** Только у них в шаблонах есть таблицы под точки.
Для УЗТ пять замеров и минимум формулой, для ТВ твёрдость в МПа с пересчётом в
НВ по таблице из вашего файла (162 пары, НВ 100…500). В шаблон идут первые
четыре точки — столько мест; о непоместившихся программа говорит, а не теряет
их молча. Незанятые места очищаются, чтобы в документе не осталось видимых
`#Т3С1`.

**Средства НК выбираются из списка**, а подставляются наименование, тип,
заводской номер и срок поверки. В вашем шаблоне акта ВИК они стояли текстом
вместе с датами поверки, и даты устаревали незаметно.

**В протокол идут два средства — столько мест в шаблоне.** Реальный комплект
больше, поэтому его полный состав ведётся на листе «Применённые средства НК»:
строка на «работа + метод + прибор». По нему проверяется комплект и сроки
поверки, а в документ уходят первые два.

### 4.4б. Выбор без ID

Идентификаторы нужны системе для связи листов, но человеку они ничего не говорят:
цифры, которые невозможно ни узнать, ни запомнить. Поэтому **выбирается всегда
читаемое обозначение**, а ID подставляется формулой в соседнюю серую колонку.

| Что выбирается | Что видно в списке |
|---|---|
| Объект контроля | `Сосуд воздушный В-1,6, зав. № 4412, рег. № 18-3007` |
| Запись журнала | `14.08.2026 · АКТ 07-2026 · Бак водоподъёмной установки  [МИГР-2026-0031]` |
| Средство НК | `Толщиномер ультразвуковой, УТ-301, зав. № 10924` |

Обозначение собирается формулой из полей самой строки — отдельного поля, которое
надо поддерживать, не появляется. Дата в обозначении записи собирается посимвольно
(`ДЕНЬ`, `МЕСЯЦ`, `ГОД`), а не через формат даты: формат зависит от региональных
настроек рабочего места, и на разных машинах список выглядел бы по-разному, а
сопоставление по тексту перестало бы работать. ID показан в квадратных скобках —
только чтобы различить две одинаковые на вид записи.

### 4.4в. Минимальный комплект приборов на метод

Требование к комплекту описывается **признаком**, а не конкретным прибором: не
«Толщиномер УТ-301 зав. № 10924», а «толщиномер». Приборы списывают и покупают
новые, а требование остаётся; привязка к инвентарному номеру пережила бы первую
же замену.

Лист «Минимальный комплект»: метод, позиция комплекта, признак для поиска,
обязательно да/нет, основание (НД, пункт). Проверка ищет признак в наименовании,
типе и назначении применённых приборов и называет недостающее — не запрещая, как
и все остальные проверки.

Лист поставляется заполненным по назначению приборов, чтобы проверка работала с
первого дня, но **колонка «Основание» намеренно пустая**: пункт вписывается из
ваших технологических карт, и только тогда позиция становится вашей.

### 4.5. Справочник объектов контроля

Объект вводится не текстом, а выбором из справочника. Причина та же, что и с ФИО:
один и тот же сосуд за три года попадёт в журнал под четырьмя написаниями, и история
по нему не соберётся.

| Поле | Содержание |
|---|---|
| ID | `ОБ-0042` — не меняется никогда |
| Каноническое наименование | как объект называется в справочнике |
| Заводской № | основной признак для поиска |
| Регистрационный № | если есть |
| Заказывающее подразделение | владелец объекта |
| Тип / группа | сосуд, трубопровод, металлоконструкция, ёмкость и т.д. |
| Место расположения | площадка, цех, установка |
| Примечание | |
| Кем внесено, Изменено | автоматически |

**Наименование в план-графике и в протоколе может не совпадать — это нормально.**
Название уточняется в процессе контроля: в план-график объект попадает под рабочим
именем, а к моменту оформления протокола выясняется точное — по паспорту, по табличке
на объекте, по заводскому номеру. Поэтому справочник объектов **не диктует** текст,
который попадёт в документ.

Работает это так:

| Где | Какое имя | Кто задаёт |
|---|---|---|
| Справочник объектов | каноническое | правится по мере уточнения, история сохраняется |
| План-график | подставляется каноническое | можно переопределить в строке плана |
| Строка журнала | поле **«Наименование в документе»** | по умолчанию — каноническое, редактируется свободно |
| Протокол, акт | берётся из «Наименование в документе» | — |

То есть в каждой строке журнала два поля: `ID объекта` (жёсткая ссылка, по ней
собирается вся история контроля) и `Наименование в документе` (свободный текст,
который печатается). Уточнили название при контроле — правите второе поле, связь с
объектом при этом не рвётся.

Если уточнённое написание оказалось правильнее канонического, макрос предлагает
одной кнопкой обновить справочник: «В документе указано «Сосуд В-1 поз. 12/3», в
справочнике — «Сосуд В-1». Обновить справочник?». Прежнее наименование уходит в поле
«Прежние наименования» — чтобы поиск по старым журналам продолжал находить объект.

**Новый объект заводится прямо из строки журнала**: если в справочнике его нет,
кнопка «Добавить объект» открывает мини-форму, а не заставляет уходить на другой лист.
Без этого справочник просто начнут обходить, вписывая текст руками.

**Карточка объекта** — по кнопке из журнала: все работы по объекту за все годы, все
методы, все номера протоколов, даты. Это то, чего сейчас нет вообще: чтобы узнать,
когда сосуд смотрели в прошлый раз, приходится листать журналы по годам.

## 5. Нумерация: черновик и регистрация

Строгая нумерация без пропусков возможна только при едином арбитре. Отсюда разделение:

| Этап | Номер | Нужна общая папка |
|---|---|---|
| Ввод результатов, формирование документа, проверка | `ЧЕРНОВИК-ПК1-007` | нет |
| **Регистрация в журнале** | `204-2026-ВИК` — выдаёт счётчик | **да, ~1 секунда** |
| Печать, сшив, передача в архив | уже с настоящим номером | нет |

Регистрация и так делается в лаборатории — там же, где печать и сшив. Выезд и
обработка результатов идут полностью автономно.

**Выдача номера** (в широком формате журнала — сразу на все отмеченные методы строки):
1. Макрос создаёт файл-блокировку `Счётчики\ВИК-2026.lock`. Если файл уже существует —
   значит, номер сейчас берёт кто-то другой; ждём и повторяем (до 5 секунд).
2. Читает число из `ВИК-2026.txt`, увеличивает, записывает обратно.
3. Удаляет блокировку.

Блокировка содержит метку времени и имя ПК: если книга упала, не сняв её, через
2 минуты она считается устаревшей и снимается автоматически, о чём пишется в журнал
операций.

Дополнительная страховка: при сборке свода мастер проверяет, что в пределах метода и
года нет двух записей с одним номером, и при совпадении выводит его в отчёт о
конфликтах. То есть даже теоретический сбой блокировки не пройдёт незамеченным.

**Формат номера — `NN-ГГГГ-Метод`.** Порядковый номер дополняется ведущим нулём до
двух знаков: `07-2026-ВИК`, `08-2026-УЗТ`. Дальше двух знаков дополнение не идёт —
`204-2026-ВИК` пишется как есть, без нулей впереди. Правило зашивается в макрос
выдачи номера, вручную его соблюдать не нужно.

Один и тот же порядковый номер в разных методах — не ошибка: счётчики независимы,
`07-2026-ВИК` и `07-2026-УЗТ` сосуществуют. Проверка на дубли (выше) работает в
пределах пары «метод + год».

**Флешка счётчики обслуживает — при одном условии.** Раньше здесь было сказано
обратное; уточняю, потому что условие изменилось. Счётчику нужен не постоянный
доступ, а **единственный арбитр**: тот, кто хранит текущее число. Два человека с
разными флешками получили бы одинаковые номера — это верно. Но **один назначенный
носитель** таким арбитром быть может ровно так же, как сетевая папка: он физически
один, и одновременно к нему обращаются не чаще, чем к серверу.

Разница только в том, что носитель не всегда подключён. Это не мешает: регистрация
и так делается в лаборатории, а не на выезде.

**Путь к общей папке определяется сам.** Носитель ищется по серийному номеру тома,
а не по букве диска: `E:` сегодня и `F:` завтра — обычное дело, а серийный номер
не меняется. Порядок поиска: сетевой путь, если он заполнен и доступен; иначе
штатная флешка; иначе обмена нет — и тогда работа идёт с черновыми номерами.
Появится сеть — путь вписывается в настройках, и он начинает использоваться
автоматически, без переделки чего-либо.

**Каждый выданный номер дописывается в реестр на носителе** (`Счётчики\Выданные-ВИК-2026.csv`):
номер, рабочее место, сотрудник, время. Файл счётчика хранит только последнее число,
а реестр — всю историю. Пока сети нет и книги живут порознь, это единственное место,
где видна вся выданная нумерация сразу; по нему же счётчик восстанавливается, если
файл счётчика потеряется.

**Регистрация пакетом.** Носитель ходит по рукам и оказывается у сотрудника на
несколько минут. Поэтому есть «Зарегистрировать все черновики»: разом по всем
накопившимся записям, с пропуском тех, где чего-то не хватает, и перечнем причин
в конце. По одной записи это делать неудобно, а неудобное перестают делать.

## 6. Обмен и слияние

### 6.1. Формат дельты

Обычный CSV, одна строка = одна запись, разделитель `;`:

```
ТипЗаписи;ID;Действие;Автор;МеткаВремени;Поле1;Поле2;…
ЖУРНАЛ;М-2026-0147;ИЗМ;Матяш;2026-09-01T14:32:11;…
СИ;СИ-0012;ИЗМ;Сиволап;2026-09-01T14:35:02;…
КТОГДЕ;КГ-0031;НОВ;Бирюков;2026-09-01T15:01:44;…
```

Действия: `НОВ` (создана), `ИЗМ` (изменена), `УДЛ` (помечена удалённой — физически
записи не удаляются, чтобы удаление не «воскресало» при следующем слиянии).

### 6.2. Порядок

1. **Специалист → «Отправить мои изменения»**: всё, что изменилось с прошлой отправки,
   выгружается одним файлом во `Входящие\`.
2. **Мастер → «Собрать свод»**: читает все файлы из `Входящие\`, сортирует записи по
   метке времени, применяет к своей копии, публикует `Свод\ЛНК_Свод.xlsx` и, если были
   спорные правки, `Конфликты\Конфликты_ДАТА.csv`. Обработанные дельты переносятся в
   `Обработанные\ГГГГ-ММ\` и **не удаляются** — это история изменений и запасной путь
   восстановления данных (16.4).
3. **Все → «Получить свод»**: локальные данные обновляются из свода.

Перед получением свода книга проверяет, есть ли неотправленные локальные правки, и
предлагает сначала отправить их — иначе они будут потеряны при обновлении.

### 6.3. Конфликты

- **Журнал**: конфликтов практически не бывает — записи добавляются, а номера уникальны
  по построению. Правка чужой зарегистрированной записи требует подтверждения.
- **Справочники**: если одну и ту же запись после прошлого свода правили двое,
  применяется более поздняя по времени, а **обе версии попадают в отчёт о конфликтах**.
  Молча ничего не теряется — мастер видит список и решает, надо ли поправить руками.

Для трёх — и даже для шести — человек, правящих справочники несколько раз в неделю,
реальное пересечение по одной и той же записи — редкость. Разбирать вручную придётся
единичные случаи. Нагрузка на мастера от числа рабочих мест почти не зависит: сборка
свода — одна кнопка, растёт только длина отчёта о конфликтах.

## 7. Синхронизация и работа без сети

- Автоматически при открытии книги и при закрытии.
- По таймеру каждые 10 минут — молча, если ничего нового.
- Кнопка «Синхронизировать» на Меню.
- Индикатор состояния на Меню: `Последняя синхронизация 14:32 ✓ сеть` /
  `⚠ Нет сети — работаем автономно, 3 изменения ждут отправки`.

Обрыв сети в момент обмена не портит данные: дельта либо доехала целиком, либо не
доехала и уйдёт в следующую синхронизацию. Файл свода публикуется через временное имя
с последующим переименованием — недописанный свод никто не прочитает.

## 8. Проверки перед действиями (эргономика)

Все проверки — **предупреждение с возможностью продолжить**, а не жёсткая блокировка.
Решение остаётся за человеком, но «не заметить» проблему нельзя.

| Действие | Что проверяется |
|---|---|
| Назначение исполнителя в План-график / Задачи / Журнал | Аттестован по этому методу на эту дату; не отсутствует по реестру «Кто где» |
| Формирование документа | Аттестация исполнителя действительна на дату контроля; отмечен минимальный комплект приборов по методу; нет просроченной поверки у применённых средств |
| Регистрация в журнале | Заполнены обязательные поля; номер получен через счётчик |
| Открытие книги | Просрочки по СИ, аттестациям, инструктажам, НД (уже реализовано на пульте) |

## 8а. Пульт: плитки и кнопки на одном листе

Было два листа — «Меню» со строками, запускавшимися двойным щелчком, и
«Дашборд» со сроками. Двойной щелчок приходится объяснять каждому новому
человеку, а Дашборд на отдельном листе смотрят по случаю. Стало одно:

- сверху **плитки** — что просрочено, что истекает, сколько черновиков ждёт
  номеров, как идёт план месяца; плитка появляется, только если по ней есть
  что делать;
- ниже **кнопки** разделами, справа от каждой — строка о том, что она делает.

Кнопки — элементы управления формы, не ActiveX: они переживают копирование
книги между машинами и не требуют ни ссылок на библиотеки, ни регистрации.
Обработчик один на все: какая нажата, кнопка сообщает своим именем через
`Application.Caller`, поэтому разбирать надписи с их пробелами не нужно.

Пульт пересобирается при открытии книги и по кнопке: число плиток меняется
день ото дня, и кнопки начинаются с той строки, где кончились плитки.

## 8б. Плановые и внеплановые работы

Разделение не вводится руками. Работа считается плановой, если в плане-графике
есть строка, привязанная к этой записи журнала; связь ставится кнопкой
«Отметить выполнение по плану», которая сама ищет незакрытую строку по объекту
и месяцу. Колонка «Вид работ» в журнале — формула, а не поле ввода.

Причина: галочку «плановая» человек рано или поздно поставит там, где плана не
было, а вопрос «сколько сделали сверх плана» задают именно тогда, когда
галочкам уже не верят. Отчёт за месяц или год — отдельной кнопкой: план,
выполнение, перечень внеплановых работ.

## 9. Формирование документов, печать, сшив

Переиспользуется всё, что уже собрано: 8 шаблонов Word с плейсхолдерами `#Поле` и
макрос подстановки.

**Схемы и картинки живут в шаблонах, а не в коде.** Собирать схему точек
программно означало бы писать рисование под каждый тип объекта; вместо этого
схема вставляется в файл шаблона один раз, и разным схемам соответствуют разные
файлы: `Протокол_УЗТ__Сосуд.docx`, `Протокол_УЗТ__Баллон.docx` при общем
`Протокол_УЗТ.docx`. Имя варианта отделено двумя подчёркиваниями. Вариант
берётся по типу объекта из справочника, а колонка «Вариант шаблона» на листе
«Данные протоколов» перебивает этот выбор для конкретной работы. Если файла
варианта нет — берётся общий шаблон. Новый набор схем добавляется файлом в
папку, без правки кода.

**Второй способ — картинка вставляется программой.** Свой файл шаблона на каждую
схему хорош, пока схем немного; когда их десятки, правку шапки надо повторить во
всех, и где-то не повторят. Поэтому в шаблоне можно поставить `#Схема_контроля`,
а картинки держать в папке схем: шаблон один на метод, схем под него сколько
угодно. Соответствие «метод + вариант → файл» — на листе «Схемы контроля», там
же размер рамки и подпись.

Размер задаётся **рамкой**, а не картинкой: изображение вписывается в рамку
целиком, с сохранением пропорций. Поэтому схема не растянет таблицу и не уедет
на другую страницу, а скан в другом разрешении встанет так же, как предыдущий.
Растянуть по рамке было бы проще, но схема с искажёнными пропорциями читается
хуже.

Что автоматизируется:
- подстановка в шаблон данных из журнала и справочников;
- сборка документов одного объекта в один файл со сквозной нумерацией, без номера на
  первой странице, с пустым листом в конце под сшив;
- печать в 3 экземплярах, двусторонняя.

**Сканы-картинки идут внутрь пакета.** Скан в JPG, PNG или TIFF Word вставляет
сам, поэтому свидетельства лаборатории, удостоверения исполнителей и
свидетельства о поверке применённых приборов становятся обычными страницами
свода: по 4 на лист, каждый раздел с новой страницы, в общей нумерации и в
подсчёте на бирке. Ищутся они по имени файла — в нём должен быть заводской
номер прибора или фамилия специалиста; требовать точного имени нельзя, файлы
называют люди.

Картинки кладутся в таблицу с точно заданной высотой строк и вписываются в
ячейку с сохранением пропорций: четвёртый скан не съезжает на следующую
страницу из-за того, что второй оказался выше.

**Сканы в PDF** (часть сканируют в JPG, часть в PDF — это данность, а не то, что
можно устранить общим требованием) Word вставить как картинку не может. В
лаборатории есть Acrobat, не только Reader, поэтому такие файлы объединяются
программно — через `AcroExch.PDDoc.InsertPages`, ту же связку методов, которой
уже не первый десяток лет пользуются для склейки PDF из VBA — тем же признаком
поиска, в те же три раздела, в том же порядке, в один файл. Число страниц в нём
Acrobat сообщает сам, вводить его вручную не нужно.

Что остаётся ручным — и это уже не ограничение набора программ, а сознательный
выбор: объединённый файл печатается и вкладывается отдельным блоком, вне общей
нумерации пакета. Поставить на уже готовый PDF номер «по листам» программно
можно только через JavaScript Acrobat, а вызовы такого рода из автоматизации
Acrobat не везде разрешены его настройками безопасности — рисковать этим ради
номеров на сканах чужих свидетельств мы не стали. Если объединение не удалось
(Acrobat не нашёлся, скан повреждён), число листов по-прежнему вводится
руками, как раньше. Если сканер переключить на JPEG, ручного не остаётся
ничего вовсе.

**Нумерация — по листам, а не по страницам.** При двусторонней печати лист несёт
две страницы, а номер у него один: он ставится на лицевых сторонах и считает
листы (страницы 1, 3, 5 → номера 1, 2, 3), на первом листе номера нет.
Переключается настройкой. Считает это вложенное поле Word `{=INT((PAGE+1)/2)}`;
собрать его из VBA одной строкой нельзя, поэтому оно собирается в два приёма, а
результат проверяется — не понял Word поле, пакет нумеруется по страницам и об
этом говорится вслух.

## 10. Формирование Паспорта ЛНК из реестров

### 10.1. Зачем

Шесть разделов Паспорта из одиннадцати — это таблицы, которые уже ведутся в реестрах.
Сейчас они живут в Паспорте отдельной копией и стареют: в присланной редакции №6 у
практически всех средств измерений с годовым циклом стоят даты поверки, истёкшие
в 2025 году. Пока Паспорт набирается руками, это будет повторяться.

Если Паспорт **собирается из реестров по кнопке**, устареть он не может в принципе,
а сама сборка становится проверкой: перед выпуском система показывает всё, что
просрочено или не заполнено.

### 10.2. Откуда берётся каждый раздел

| Раздел Паспорта | Источник |
|---|---|
| 1. Общие данные | Лист «Паспорт — постоянная часть» |
| 2. Профессиональная квалификация сотрудников | Реестры «Специалисты» + «Аттестации» |
| 3. Объекты неразрушающего контроля | Постоянная часть (область аттестации) |
| 4. Виды (методы) неразрушающего контроля | Постоянная часть (область аттестации) |
| 5. Оснащённость средствами НК | Реестр «СИ», раздел = «Средства НК», с группировкой по методу |
| 6. Меры, контрольные и настроечные образцы | Реестр «СИ», раздел = «Меры и образцы» |
| 7. Дозиметрические и радиометрические СИ | Реестр «СИ», раздел = «Дозиметрия» |
| 8. Вспомогательное оборудование | Реестр «СИ», раздел = «Вспомогательное» |
| 9. Перечень нормативных документов | Реестр «НД» |
| 10. Помещения | Постоянная часть |
| 11. Передвижные лаборатории | Постоянная часть |

Новый лист **«Паспорт — постоянная часть»** держит то, что меняется раз в несколько
лет: реквизиты, ответственные лица с телефонами, область аттестации, помещения,
номер редакции и дату. Заполняется один раз.

**Заполняется вручную по шаблону.** Лист делается пустым, но не голым: каждая строка
подписана, рядом столбец «Подсказка» с тем, что именно сюда вносится и в каком виде,
и указанием, в какой раздел и колонку Паспорта поле попадёт. Обязательные поля
подсвечены; пока они пустые, сборка Паспорта выдаёт список незаполненного и не
формирует документ (раздел 10.5).

Так что действующую редакцию №6 присылать не нужно. Единственное следствие: сверить
получившийся Паспорт с прошлой редакцией всё-таки стоит — при первой сборке, глазами,
один раз. Это дешевле, чем искать расхождение через год.

### 10.3. Что для этого нужно добавить в реестры

Разделы Паспорта содержат поля, которых в текущих реестрах нет. Их надо завести
**до** реализации, иначе сборка будет с пробелами.

**Реестр «СИ»:**

| Новое поле | Зачем |
|---|---|
| Раздел паспорта | Средства НК / Меры и образцы / Дозиметрия / Вспомогательное — определяет, в какой раздел попадёт запись |
| Метод контроля | Группировка внутри раздела 5 (ВИК, УЗТ, АЭ…) |
| Назначение | Колонка 3 Паспорта — что именно измеряет прибор |
| Технические и метрологические характеристики | Колонка 5 — диапазоны, погрешности; длинный текст |
| Владелец оборудования, основание владения | Колонка 6 |

**Реестр «Специалисты»:**

| Новое поле | Зачем |
|---|---|
| Основание привлечения | Трудовой договор / ГПХ / совместительство — колонка 3 Паспорта |
| Образование, повышение квалификации, стаж | Колонка 5 — длинный текст с перечнем программ обучения и датой начала стажа |
| Функции в ЛНК | Ответственный за метрологическое обеспечение, за фонд НД и т.д. — идёт в колонку 4 вместе с должностью |

Поля «Изготовитель», «Заводской №», «Год выпуска», «Дата ввода в эксплуатацию» в
реестре уже есть по отдельности — при сборке они склеиваются в одну ячейку Паспорта
в принятом там виде.

### 10.4. Как собирается

Технически это отличается от актов и протоколов: там таблицы фиксированной длины и
хватает замены `#Поля`, здесь количество строк заранее неизвестно.

Шаблон `Паспорт_ЛНК.docx` содержит постоянный текст и таблицы, в каждой из которых
**одна строка-образец** с маркерами. Макрос:

1. считает, сколько записей попадает в раздел;
2. дублирует строку-образец нужное число раз, сохраняя форматирование;
3. подставляет значения;
4. удаляет исходный образец;
5. в разделе 5 дополнительно вставляет подзаголовки по методам контроля.

### 10.5. Проверка перед выпуском

Перед сборкой выводится список того, что попадёт в документ некорректным:

- средства измерений с истёкшей поверкой или калибровкой;
- специалисты с истёкшей аттестацией;
- нормативные документы, не проходившие проверку на актуальность более года;
- незаполненные обязательные поля (назначение, характеристики, основание владения).

Выпуск можно продолжить с подтверждением — но «не заметить» уже нельзя. Именно этой
проверки не хватало, чтобы редакция №6 не ушла с просроченными датами.

### 10.6. Редакции

Номер редакции и дата хранятся в постоянной части. При сборке предлагается увеличить
номер; готовый файл сохраняется как `Готовые\Паспорт\Паспорт_ЛНК_Ред7_2026-09-01.docx`,
предыдущие редакции остаются на месте — история не затирается.

### 10.7. Срок аттестации самой ЛНК — на пульт

Паспорт входит в комплект для аттестации лаборатории, а у самого **свидетельства об
аттестации ЛНК есть срок действия**. Сейчас он не отслеживается нигде, хотя это самый
дорогой по последствиям срок во всей системе: с его истечением лаборатория не может
работать вообще, в отличие от одного просроченного прибора.

Решено выводить. Реализация: поля «№ свидетельства об аттестации ЛНК», «Дата выдачи»,
«Действительно до» и «Орган по аттестации» живут на листе «Паспорт — постоянная часть»
(они и так требуются разделом 1 Паспорта), а на пульте появляется отдельная плитка
первой строкой — выше сроков по приборам и специалистам.

Пороги предупреждения здесь другие, чем у остального: подготовка к переаттестации
занимает месяцы, поэтому плитка желтеет за **180 дней** и краснеет за 90. Дату можно
внести позже — до тех пор плитка показывает «срок не заполнен» и не притворяется, что
всё в порядке.

## 11. Обслуживание оборудования: учёт и план-графики

### 11.1. Что требуют ваши Правила

«Правила организации и проведения поверки и технического обслуживания средств НК»
предусматривают две формы, которые надо уметь выпускать:

- **Приложение №6** — пятилетний план-график планово-предупредительных осмотров и ремонтов;
- **Приложение №7** — месячный план-график ППР.

Плюс карточка учёта средства НК (Приложение №1) содержит подтаблицу «Сведения о ремонте
и техническом обслуживании» — её тоже нужно чем-то наполнять.

### 11.2. Реестр «Обслуживание СИ» — факт выполненных работ

Одна строка = одно выполненное мероприятие. Из него же печатается подтаблица карточки
учёта, чтобы не вести одно и то же дважды.

| Поле | Содержание |
|---|---|
| ID | `ОБ-0045` |
| ID средства НК | ссылка на реестр «СИ» |
| Дата проведения | дата |
| Вид работ | ТО / Текущий ремонт / Средний ремонт / Внеплановое / Проверка после транспортировки |
| Содержание работ | текст |
| Исполнитель | свой сотрудник или сторонняя организация |
| Результат | Исправен / Неисправен / Выведен из эксплуатации |
| Трудозатраты, ч | для расчёта итогов план-графика |
| Израсходовано спирта, г | графа есть в вашей месячной форме |
| Основание | № договора, акта |
| Примечание | |

### 11.3. Что добавить в реестр «СИ» для планирования

Уточнено по вашему действующему план-графику (учётный номер 605-2025.ПЛ).

| Новое поле | Зачем |
|---|---|
| **№ карточки учёта средства НК** | Ключевое поле: именно по нему план-график связан с приборами. Бывает диапазоном (`1…9`, `37..45, 61`) — одна карточка на комплект |
| Маркировка согласно схеме | Колонка 3 месячной формы |
| Единица измерения, Количество | Колонки 5-6 |
| Виды ТО с периодичностью и нормой | **Отдельной подтаблицей, а не полями** — см. ниже |

**Почему подтаблица, а не колонки.** В вашем графике один прибор занимает несколько
строк: «Виброанализатор СД-23» (карточка 53) идёт дважды — с ТО-2 и с ТО-4, весы
М-ER 122ACF — с ТО-1 и ТО-4, комплекс LASERTECH 900 — с ТО-2 и ТО-4. Плоские поля
«периодичность ТО / ТР / СР» этого не выражают. Поэтому у прибора будет список видов
обслуживания: вид, периодичность, норма трудозатрат, — сколько нужно, столько строк.

**Группу обслуживания завожу, но не требую.** В вашем графике колонка 4 пустая по всем
44 строкам — значит, на практике она не используется. Поле останется на случай, если
понадобится, но заполнять его никто не обязан.

**ТР и СР — то же самое.** Колонки периодичности и норм по текущему и среднему ремонту
в графике пустые: планируется только ТО. Поля предусмотрены, план по ним не строится,
пока не появятся значения.

С учётом полей для Паспорта (раздел 10.3) реестр «СИ» становится широким — порядка
35 колонок. Редактировать такое построчно в листе неудобно, поэтому для него нужна
**карточка прибора**: отдельная форма, где одна запись показана вертикально, полями
сверху вниз. Ввод идёт через неё, лист остаётся для просмотра и фильтрации.

### 11.4. Откуда берутся периодичность и нормы

Из **действующего пятилетнего план-графика ППР на 2026-2030 гг.** (учётный номер
605-2025.ПЛ), лист «Пятилетний». Он получен, разобран, вопрос закрыт.

**Связка с реестром СИ — по номеру карточки учёта**, колонка 3 графика. Это надёжнее
заводского номера: в графике 44 строки, и часть из них ссылается на диапазон карточек
(`1…9` — комплект «ВИК-НК», `37..45, 61` — комплект «ЭКСПЕРТ №1», `30..32` — три меры
твёрдости). По наименованию связать не получилось бы: в графике оно с переносами строк
и лишними пробелами («Люксметр «Testo 540»,⎵⎵⎵⎵зав. № 39081375/801»).

**Категории ТО.** В графике периодичность записана парой «число / ТО-N», где число —
доля года. Расшифровка получается такая:

| Категория | Число в графике | Что это | Операций в год |
|---|---|---|---|
| ТО-1 | 0,0027 | 1/365 — ежедневно | 244 в 2026 (по рабочим дням) |
| ТО-2 | 0,027 | 10/365 — подекадно | 32 (по 3-3-2 в квартал) |
| ТО-3 | 0,083 | 1/12 — ежемесячно | 12 |
| ТО-4 | 0,25 | 1/4 — ежеквартально | 4 |

Расшифровка выведена из арифметики самого файла, в нём она нигде не написана.
**Подтверждена** — на ней и построен расчёт плана обслуживания.

**Помесячная раскладка переносится как есть, а не пересчитывается.** График подписан
и утверждён; расчёт заново дал бы другие числа (декадное ТО дало бы 36 операций в год
вместо ваших 32) и разошёлся бы с документом. Пересчёт делается кнопкой — и только
когда будете составлять следующий пятилетний график.

**Сверка после переноса.** Печатается таблица в обе стороны: карточки из графика,
которых нет в реестре СИ, и приборы из реестра, которых нет в графике. Первое обычно
списанное, второе — забытое при составлении.

### 11.5. Как считается план

Дата следующего мероприятия = дата последнего мероприятия **того же вида** из реестра
«Обслуживание» + периодичность. Если мероприятие не проводилось ни разу — считается от
даты ввода в эксплуатацию.

Отметка в клетке месяца ставится тем приборам, у которых расчётная дата попадает в этот
месяц. Итоги трудозатрат по месяцу и по году — суммой норм по отмеченным работам.

### 11.5а. Что нашлось в присланном план-графике

Разбор файла заодно показал несколько мест, которые стоит поправить в самом документе.
Ни одно не мешает переносу — я их обхожу, — но в подписанном графике они остаются.

1. **Норма трудозатрат у твердомера «ТКМ-459С» (строка 13) записана текстом**, а не
   числом: `0.5` с точкой вместо запятой. Excel такую ячейку в суммы не берёт — если
   где-то считается итог по колонке норм, этот прибор из него выпадает.
2. **У твердомера «ТЕМП-4» (строка 14) не заполнено количество.** Трудозатраты при этом
   проставлены, то есть формула итога на количество не опирается — но проверить стоит.
3. **Настроечный образец «ОК 6-1,3-1,2» (строка 31) в 2026 году отмечен 10 раз**, хотя
   периодичность у него ТО-4, квартальная, и в 2027-2030 стоит по 4 отметки. Похоже на
   случайную протяжку.
4. **Нумерация обрывается: 1-44, затем 47-54** на восьми пустых строках. Номера 45 и 46
   отсутствуют. Скорее всего остаток от удалённых строк.
5. Заголовок над 2027 годом задублирован: «2027 г.⎵⎵…⎵⎵2027 г.».

Первые три — содержательные, остальные косметические. При переносе я беру данные как
есть и по каждому пункту выведу строку в отчёте сверки, чтобы вы решили, править ли
исходный документ.

### 11.6. Печатные формы

- **Пятилетний план-график ППР** (Прил.6) — строки приборы, колонки 5 лет × 12 месяцев
  плюс графы норм и итогов. Формируется на выбранный стартовый год.
- **Месячный план-график ППР** (Прил.7) — только приборы с мероприятиями в этом месяце,
  колонки дни 1-31 с отметкой «Р», графа расхода спирта, подписи исполнителя и
  принявшего работу.

Обе собираются той же техникой таблиц переменной длины, что и Паспорт (раздел 10.4).

### 11.7. Связь с пультом

Ближайшие ТО и ремонты выводятся рядом с поверками — та же логика «просрочено /
истекает», отличается только источник срока.

### 11.8. Заявка на поверку на год — входит в этап 7

По вашим же Правилам заявки на поверку формируются на календарный год и направляются
в метрологическую службу, которая строит свой план-график. Заявка — это выборка из
реестра «СИ» тех приборов, у которых поверка истекает в планируемом году.

Кнопка «Заявка на поверку на год» на листе «СИ»: спрашивает год (по умолчанию
следующий), собирает все приборы со сроком поверки внутри этого года и выводит
готовую форму — наименование, тип, заводской №, год выпуска, дата последней поверки,
дата истечения, квартал подачи. Сортировка по кварталам, чтобы заявка сразу читалась
как график.

Отдельно выводятся приборы, у которых дата поверки в реестре не заполнена: они не
попадут в заявку молча, а будут показаны списком «проверьте эти приборы».

## 12. Журнал выдачи оборудования

### 12.1. Форма

| Поле | Содержание |

| № п/п | в пределах года |
| Дата выдачи | дата |
| ID средства НК | **выбор из реестра «СИ»** — наименование, тип и зав. № подставляются сами |
| Назначение выдачи | Измерения / Поверка / Ремонт / Временная выдача в подразделение |
| Состояние при выдаче | Исправен / Неисправен |
| Кому выдано | из справочника специалистов либо текст для сторонних |
| Дата возврата | пусто, пока не вернули |
| Состояние при возврате | Исправен / Неисправен |
| Примечание | |

Графы подписей получившего и принявшего заполняются на распечатке — в электронной
таблице они не нужны, а на бумаге обязательны.

Прибор выбирается из реестра, а не вписывается текстом. Иначе через год половина
записей будет с разным написанием одного и того же прибора, и вопрос «где сейчас
толщиномер» останется без ответа.

### 12.1а. Выдача, вытекающая из контроля

Прибор, которым провели контроль, к моменту контроля был у исполнителя на руках.
Требовать, чтобы тот же факт вписали вторично отдельной строкой «выдал —
принял», значит просить человека доказывать очевидное; на третий раз это
перестают делать, и журнал выдачи расходится с журналом заключений — причём
расходится молча.

Поэтому **строки журнала выдачи по работам НК заводятся из применённых средств**:
при регистрации записи, датой контроля, на исполнителя метода, с основанием
«Контроль по акту …, метод …». Правило разрешения:

| Состояние на дату контроля | Что делает система |
|---|---|
| Прибор не числится выданным | заводит строку: выдача и возврат одним днём |
| Числится выданным тому же исполнителю | ничего — факт уже учтён |
| Числится за другим человеком | не трогает, а называет расхождение |

Одним днём — потому что иначе через неделю на пульте окажется полсотни
«невозвращённых» приборов, стоящих на своих местах, и предупреждение про
действительно невозвращённый перестанут читать. Прибор, оставшийся на руках,
выдают обычным порядком, и тогда открытая строка закрывает все дни работ —
новых не появляется.

Ручная выдача остаётся для всего, чего работа по НК не объясняет: обслуживание,
поверка, командировка.

### 12.2. Проверки при выдаче

- **Прибор уже числится выданным** и не возвращён — предупреждение с указанием, кому
  и с какой даты. Это основная причина, по которой приборы теряются.
- **Поверка просрочена, а назначение выдачи — «Измерения»** — предупреждение: измерять
  таким прибором нельзя. При выдаче на поверку или в ремонт просрочка нормальна, за
  этим прибор и выдают, поэтому там предупреждения быть не должно.
- **Прибор помечен неисправным**, а выдаётся на измерения — предупреждение.

### 12.3. На пульте

Плитка «Выдано и не возвращено» со списком по клику, и отдельно — «на поверке» и
«в ремонте». Это приборы, физически отсутствующие в лаборатории: при планировании
работ на неделю вперёд это надо видеть заранее, а не в день выезда.

## 13. Рекламации и претензии

Правила рассмотрения рекламаций (Редакция №1) получены — последний недостающий
документ системы менеджмента. Форма журнала известна, раздел строится по ней.

### 13.1. Журнал учёта рекламаций, претензий

Строго по Приложению №1 к Правилам, восемь граф:

| № | Графа |
|---|---|
| 1 | № п/п |
| 2 | Реквизиты документа |
| 3 | Дата регистрации в ЛНК |
| 4 | Подразделение, от кого поступил документ |
| 5 | Срок выполнения |
| 6 | ФИО кому выдан, роспись о получении |
| 7 | Отметка об выполненных мероприятиях |
| 8 | Примечание |

Графа 6 содержит роспись — значит, лист печатается и подписывается от руки. В
электронном виде ведутся все графы, кроме подписи; в печатной форме под неё
оставляется место.

Служебно, как и везде: ID записи, кем внесено, изменено.

### 13.2. Что система делает сама

**Контроль срока.** Графа 5 — срок выполнения; графа 7 пустая означает, что
мероприятия не выполнены. Отсюда плитка на пульте: «Рекламации: 1 просрочена,
2 в работе». Это единственный журнал, где срок задаётся вручную по каждой записи,
а не считается по периодичности, — поэтому и контролировать его иначе нечем.

**Связка с заключением.** Правила требуют при выявлении неверных результатов выдать
новое заключение за новым номером, а старое аннулировать с записью в Журнале выдачи
заключений. Значит, в записи о рекламации нужны две ссылки: на аннулируемое
заключение и на выданное взамен.

Аннулирование делается не правкой строки журнала, а отдельным действием: у записи
появляется статус «Аннулировано», дата, основание и номер заменяющего документа.
Сама строка остаётся на месте — иначе нумерация журнала пойдёт с дырой, а по вашим
же Правилам аннулированное заключение должно быть в журнале видно.

**Связка с корректирующими действиями.** Правила требуют по итогам разбирательства
внести запись в Журнал учёта корректирующих действий. Кнопка «Создать корректирующее
действие» из строки рекламации заводит связанную запись, чтобы эта цепочка не
держалась на памяти.

### 13.3. Чего система делать не будет

Комиссия, разбирательство, докладная записка начальнику структурного подразделения,
решение о повторном контроле — это работа людей, а не программы. Система хранит
результат: дату, состав комиссии, принятое решение, ссылку на файл докладной.

Отдельно: Правила разрешают ЛНК не рассматривать рекламации, связанные с формами
документов и процедурами, предусмотренными нормативно-правовыми документами. Такой
случай в журнале — обычная запись с решением «мотивированный отказ», а не пропуск.

### 13.4. Лист ознакомления

**В системе.** Приложение №2 к Правилам — лист ознакомления сотрудников. Такой же лист
есть у каждого документа системы менеджмента, поэтому форма делается общей: документ,
редакция, должность, ФИО, подпись, дата. Кнопка «Лист ознакомления» (`modSM.bas`)
спрашивает название документа и редакцию и строит печатную форму — ФИО и должности
подставляются из реестра специалистов, подпись и дата ставятся от руки при
подписании.

## 14. Годовая печать и сшив журналов

По вашим Правилам журналы по завершении года распечатываются, прошиваются, визируются
подписями и сдаются в архив. Порядок одинаков для всех журналов, поэтому механизм
делается **один общий**, с выбором, что печатать:

- журнал учёта заключений — по каждому методу отдельно;
- журнал выдачи оборудования;
- журнал учёта инструктажей;
- журнал входного контроля средств НК — если решите вести и его, форма есть в
  Приложении №3 ваших Правил.

Что делает макрос «Печать журнала за год»:

1. отбирает записи выбранного журнала за указанный год;
2. формирует титульный лист по вашему образцу — наименование, год, учётный номер вида
   `00-2020.РЖ`, поля «Начат» и «Окончен»;
3. собирает таблицу с постраничной разбивкой и повторением шапки на каждой странице;
4. проставляет сквозную нумерацию, без номера на первой странице;
5. добавляет пустой лист в конце под бирку сшива;
6. отправляет на печать в нужном числе экземпляров.

Это тот же механизм, что уже спроектирован для пакета документов по акту (раздел 9) —
отличается только источником строк.

## 15. Обновление версии программы

### 15.1. Через общую папку

В `Версия\версия.txt` — номер актуальной версии, дата, кто выпустил и контрольная сумма
файла. Книга при открытии сравнивает со своей и, если в общей папке новее, предлагает
обновиться: копирует `ЛНК_Программа.xlsm` к себе и перезапускается. `ЛНК_Данные.xlsx`
не затрагивается.

Копирование — по подтверждению пользователя, а не автоматически: перезапись файла,
который может быть открыт, ломает больше, чем чинит.

Перед заменой книга проверяет контрольную сумму скопированного файла (SHA-256 через
штатный `certutil`, он есть в Windows и прав администратора не требует). Не совпала —
обновление отменяется, старая версия остаётся на месте. Это ловит и оборвавшееся
копирование по нестабильной сети, и подменённый файл.

Предыдущая версия не удаляется, а уезжает в `Версии\ЛНК_Программа_v1.4.xlsm`. Откат —
это переименование файла, а не восстановление из копии.

### 15.2. Обновление с флешки — один назначенный носитель

Решено: обмен и обновление через флешку идут **только с одного назначенного носителя**.

**Как программа его опознаёт.** Не по букве диска (она меняется от машины к машине) и
не по названию папки (её можно создать где угодно), а по **серийному номеру тома** —
это число присваивается носителю при форматировании и читается из VBA штатно
(`FileSystemObject.Drives("E:").SerialNumber`). Скопировать папку на другую флешку
можно, а серийный номер — нет.

Разрешённые серийные номера лежат в файле `Версия\носители.txt` в общей папке; пишет
его только мастер. При работе с флешкой книга:

1. перебирает подключённые съёмные диски;
2. ищет среди них тот, чей серийный номер есть в списке разрешённых;
3. не нашла — отказывается читать и писать, с внятным сообщением:
   «Обмен разрешён только с носителем ЛНК-Обмен (сер. № 1A2B-3C4D). Подключён носитель
   с сер. № 9F8E-7D6C. Возьмите штатную флешку у мастера.»

Никакого молчаливого отказа: сообщение называет и то, что ожидалось, и то, что нашлось.

**Регистрируется два носителя, а не один.** Основной в работе, резервный лежит у
мастера. Иначе потерянная или умершая флешка останавливает обмен целиком, а флешка —
самая ненадёжная часть всей системы: её носят в кармане, втыкают по десять раз в день
и теряют. Замена носителя — процедура мастера: подключил, нажал «Зарегистрировать
носитель», старый серийный номер ушёл в архив списка с датой и причиной.

**Физическая маркировка.** Метка тома `LNK-OBMEN`, наклейка на корпусе, в корне —
файл `ПРОЧТИ.txt` с назначением флешки и телефоном мастера. Это не защита, а способ
вернуть найденную флешку и не отформатировать её под музыку.

**Честно про границы этого механизма.** Без прав администратора запретить подключение
других флешек к компьютеру нельзя — это делается политиками Windows, которых у вас нет.
Ограничение работает на уровне программы: она откажется обмениваться данными с чужим
носителем. Это защита **от ошибки**, а не от намерения: тот, кто захочет, всё равно
скопирует файлы проводником. Ценность в другом — «я думал, эта флешка тоже подойдёт»
и «я вчера скинул свод на свою, а сегодня несу её» перестают быть возможными.
От подмены файла на флешке защищает не привязка к носителю, а контрольная сумма
из 14.1.

Дополнительно: обновление никогда не запускается **с** флешки. Файл сначала копируется
на локальный диск, проверяется по контрольной сумме и открывается уже оттуда. Флешка,
ходящая между машинами, — обычный путь для заражения, и запуск чего-либо прямо с неё
этому только помогает.

## 16. Резервное копирование

Вопрос был открыт, закрываю его целиком. Резервное копирование здесь не
факультативная опция: журнал заключений и реестры — учётные документы, срок хранения
которых задан вашими же Правилами учёта документации, а Excel-файл теряется от одного
неудачного сохранения.

Установить что-либо специальное нельзя, поэтому всё строится на том, что уже есть:
копирование файлов из макроса и штатные средства Windows.

### 16.1. Что вообще может пропасть

| Что | Чем грозит потеря | Насколько трудно восстановить |
|---|---|---|
| `ЛНК_Данные.xlsx` на рабочем месте | Записи, не попавшие в последний свод | Средне — есть свод и дельты |
| `ЛНК_Свод.xlsx` у мастера | Общая картина по всем методам | Тяжело, если нет истории сводов |
| `Счётчики\` | Сбой нумерации, повтор номеров | **Легко, но опасно** — см. 15.6 |
| `Готовые\` — сформированные документы | Придётся формировать заново | Легко, если журнал цел |
| `Шаблоны\` | Формы документов | Легко — меняются раз в год |
| `ЛНК_Программа.xlsm` | Сам инструмент | Легко — версии хранятся (15.1) |

Отдельно: **общая папка на сервере централизованно не резервируется** — это проверено,
а не предположено. Всё, что лежит только там (счётчики, обработанные дельты, история
сводов, опубликованные версии), защищено исключительно нашими же средствами. Отсюда
зеркало у мастера и обязательный третий уровень — см. 15.5.

Самое дорогое в этом списке — журнал. Всё остальное либо восстанавливается из него,
либо переделывается за час.

### 16.2. Уровень 1 — локальные копии на каждом рабочем месте

При закрытии книги макрос копирует `ЛНК_Данные.xlsx` в
`D:\ЛНК\Копии\ЛНК_Данные_ГГГГ-ММ-ДД.xlsx`. Одна копия в день, вторая за тот же день
перезаписывает первую.

Глубина: последние **30 дней** плюс по одной копии на первое число каждого месяца за
последние 12 месяцев. Старше — удаляется автоматически. Это порядка сорока файлов;
при типичном размере журнала счёт идёт на десятки мегабайт, а не на гигабайты.

Почему при закрытии, а не при каждом сохранении: копировать файл на каждое нажатие
Ctrl+S — это заметная пауза по десять раз на дню, от которой люди начинают искать,
где её отключить.

Отдельно и чаще копируется папка `Счётчики\` — при каждой выдаче номера. Файлы там
размером в десяток байт, копирование незаметно, а цена потери максимальная.

### 16.3. Уровень 2 — история сводов у мастера

Перед каждой сборкой свода мастер-макрос копирует текущий `ЛНК_Свод.xlsx` в
`Свод\История\ЛНК_Свод_ГГГГММДД-ЧЧММ.xlsx`. Хранятся последние 60 копий.

Это защита от **неудачного слияния**, а не от отказа диска: если после сборки
выяснилось, что дельта пришла битой и затёрла нужное, есть точное состояние «до».

### 16.4. Дельты — это и есть журнал изменений

Ключевое решение: **обработанные дельты не удаляются**. После применения файл
переезжает из `Входящие\` в `Обработанные\ГГГГ-ММ\`.

Дельты дописываются, а не переписываются, поэтому их набор — полная история: кто, что
и когда изменил, с начала работы системы. Из них можно собрать состояние данных на
любую дату, даже если все книги погибли одновременно. Занимают они мало: это текстовые
CSV, годовой объём — единицы мегабайт.

Побочная польза, ради которой это стоило бы делать и без резервного копирования: на
вопрос «кто и когда поменял срок поверки у этого прибора» есть точный ответ.

### 16.5. Уровень 3 — внешний носитель

Раз в неделю мастер нажимает «Резервная копия на носитель». Копируются свод, счётчики,
шаблоны, обработанные дельты и `Готовые\` за текущий год — в папку с датой.

**Это должна быть отдельная флешка, не та, что для обмена.** Флешка обмена ходит между
машинами, втыкается по десять раз в день и живёт в кармане — она из всей системы
погибнет первой. Резервный носитель должен лежать спокойно и желательно не в том же
помещении, где компьютеры: смысл внешней копии в том, чтобы пережить событие, которое
случилось с самими компьютерами.

**Сервер не резервируется — это выяснено.** Значит, послаблений нет: третий уровень
обязателен и делается еженедельно, без пропусков. Из этого следуют ещё два решения.

**Два носителя под копии, по очереди.** Нечётная неделя — носитель А, чётная — Б;
тот, что не в работе, лежит вне помещения с компьютерами. Причина не в паранойе:
копирование — это момент, когда носитель пишется, и именно тогда он чаще всего
и умирает. Один-единственный носитель означает, что неудачная запись уничтожает
и текущую копию, и предыдущую разом.

**Зеркало общей папки у мастера.** Раз сервер не резервируется, его отказ уносит
счётчики, обработанные дельты, историю сводов и опубликованные версии программы —
всё, чего нет на рабочих местах. Поэтому при каждой сборке свода мастер-макрос
дублирует общую папку целиком в `D:\ЛНК\Обмен_зеркало\` на своём диске.

Это почти бесплатно (объём — единицы мегабайт), а результат такой: отказ сервера
перестаёт быть аварией. Мастер меняет путь к общей папке на флешку или на другой
сетевой ресурс, копирует туда зеркало — и работа продолжается. Без зеркала тот же
отказ означает восстановление дельт из недельной копии и пересчёт счётчиков.

### 16.6. Восстановление счётчиков — отдельно, это ловушка

Счётчики нельзя восстанавливать из резервной копии как обычный файл. Копия недельной
давности вернёт номер, который за неделю уже был кому-то выдан, и два разных документа
получат `07-2026-ВИК`.

Поэтому счётчики восстанавливаются **не из копии, а из журнала**: макрос
«Восстановить счётчики» находит максимальный номер по каждому методу за текущий год и
ставит следующий. Тот же механизм, что при переходе (19.3), и по той же причине —
журнал первичен, счётчик лишь идёт следом.

### 16.7. Проверка копий

Копия, которую ни разу не разворачивали, — это не копия, а надежда.

- **Ежеквартально** — макрос «Проверка резервных копий»: открывает последнюю копию
  только на чтение, сверяет наличие всех листов и количество записей по методам с
  рабочим файлом, печатает отчёт на одну страницу.
- **Раз в год** — настоящее восстановление на свободном рабочем месте: развернуть
  копию, открыть, сформировать один документ. Полчаса работы, которые показывают, что
  процедура вообще работоспособна.

### 16.8. Журнал резервного копирования

Отдельный лист: дата, что копировалось, куда, размер, результат, кто выполнял.
Заполняется макросом автоматически, вручную — только отметки о ежегодном
восстановлении.

Помимо прямой пользы, это ещё и то, что предъявляется при проверке сохранности
документации: без записей утверждение «мы делаем резервные копии» ничем не
подтверждается.

### 16.9. Что делать, когда что-то пропало

Порядок действий, записанный заранее, — половина ценности резервного копирования.
Ищем ближайший уцелевший источник сверху вниз:

1. Локальная копия за вчера (16.2) — потеря максимум за день.
2. Последний свод у мастера (16.3) — потеря того, что не успело уйти дельтами.
3. Зеркало общей папки у мастера (16.5) — если отказал сервер, а не рабочее место.
4. Дельты (16.4) — восстанавливается всё, но дольше.
5. Недельная копия на внешнем носителе (16.5) — когда не уцелело ничего локального.

**Счётчики после любого восстановления пересчитываются из журнала** (16.6), а не
берутся из копии. Затем печатается сверка по методам — та же, что при переходе
(19.2), — и только после сходящегося счёта работа продолжается.

## 17. Риски, которые надо держать в голове

1. **Мастер — единая точка.** В его отсутствие свод не собирается. Смягчение: роль
   переключаемая, книга напоминает назначить временного, если мастер отмечен
   отсутствующим.
2. **Last-write-wins в справочниках** может потерять одновременную правку. Смягчение:
   отчёт о конфликтах, обе версии сохраняются.
3. **Счётчики требуют общей папки** в момент регистрации. Смягчение: черновые номера
   до появления сети.
4. **Всё держится на макросах.** Подтверждено, что они работают, но при смене политики
   безопасности система встанет целиком.
5. **Общая папка не резервируется никем, кроме нас.** Отказ сервера уносит счётчики,
   дельты и историю сводов. Смягчение: зеркало общей папки у мастера, обновляется при
   каждой сборке свода.
6. **Флешка — самое ненадёжное звено.** Носитель обмена ходит между машинами и
   изнашивается быстрее всего остального. Смягчение: зарегистрированы два носителя,
   резервные копии лежат на третьем, обновление всегда проверяется контрольной суммой.
7. **Excel — не база данных.** При 3 пользователях и нескольких тысячах строк в год
   запаса прочности достаточно. Ориентир, после которого стоит пересматривать
   архитектуру: 5+ одновременных пользователей или 20 000+ записей в журнале.

### Согласованная очерёдность

Решено: **журнал и расширение реестров делаются сразу**, до того как в систему
пойдут данные. Фактический порядок работ отличается от нумерации этапов:

| Очередь | Этапы | Почему так |
|---|---|---|
| 1 | **1, 2** — журнал, разделение программа/данные, ID, плюс локальные копии данных (16.2) | База, без неё не имеет смысла остальное. Копии включаются сразу: они стоят двадцать строк кода, а данные копятся с первого дня |
| 2 | **6, 7** — все дополнительные поля реестров (Паспорт, обслуживание) | Поля должны существовать **до** наполнения: дозаполнять полторы сотни записей задним числом дороже, чем завести колонки сразу |
| 3 | **3, 4** — счётчики и обмен | Включаются, когда структура данных уже не поменяется |
| 4 | **5, 8, 12** — «Кто где», журнал выдачи, рекламации | Независимы, можно параллельно |
| 5 | **9, 10, 11** — годовая печать, обновление версий, остальные уровни копирования | Печать нужна к декабрю. Уровни 2-3 опираются на свод и дельты и раньше этапов 3-4 не заработают |

Ключевое в этом порядке — вторая очередь. Сначала заводится **полный** состав колонок
(включая те, что нужны только Паспорту и план-графику ППР), и только потом реестры
наполняются. Иначе через месяц придётся возвращаться к каждой карточке прибора и
дописывать группу обслуживания, периодичность ТО и нормы трудозатрат.

Этапы 1-2 имеют смысл только вместе; 3 и 4 можно проверять по отдельности; 5, 8 и 9
не зависят от остальных.

Единственное, что вынесено из своей очереди вперёд, — локальные копии данных. Всё
прочее в резервном копировании опирается на свод и дельты, а копировать рабочий файл
при закрытии книги можно с первого же дня.

## 19. Переход на новую систему

Решено: **полный переход сейчас**, без параллельного ведения старого и нового
журналов. Двойной ввод не спасает, а гарантированно расходится — через две недели
никто не помнит, какой файл главный.

### 19.1. Что переносится

| Что | Объём | Как |
|---|---|---|
| Журнал за 2026 год | весь, целиком | миграция скриптом из текущего файла в широкий формат |
| Журналы прошлых лет | не переносятся | остаются в старом файле для справок |
| Справочники СИ, специалистов, НД | целиком | уже собраны в книге v2, дополняются новыми полями |
| Объекты контроля | собираются из журнала 2026 | наименования вычищаются от разнописания, дубли сводятся |

Год 2026 переносится **полностью**, а не с даты запуска. Иначе годовой журнал за 2026
придётся печатать из двух источников и сшивать вручную — ровно та работа, ради
устранения которой всё и делается.

### 19.2. Сверка после миграции

Переход не считается выполненным, пока не сойдётся счёт. Макрос миграции выдаёт
таблицу сверки:

| Метод | Записей в старом файле | Записей в новом | Расхождение |
|---|---|---|---|
| ВИК | 412 | 412 | 0 |
| УЗТ | 197 | 197 | 0 |
| … | | | |

Сверяются: количество записей по каждому методу, минимальный и максимальный номер в
серии, отсутствие пропусков в нумерации, отсутствие дублей номеров. Любое расхождение
разбирается **до** запуска, а не после.

Отдельно выводится список записей, которые не удалось разобрать автоматически
(пустой метод, номер не в формате, дата не распознана) — их доводят руками, их
обычно единицы.

### 19.3. Порядок дня перехода

1. Старый файл журнала копируется в архив под именем с датой.
2. Запускается миграция, печатается таблица сверки.
3. Расхождения устраняются, миграция повторяется — до нулевых расхождений.
4. Счётчики методов выставляются **автоматически по мигрированному журналу**:
   макрос находит максимальный номер в серии по каждому методу за 2026 год и
   показывает таблицу — метод, найденный максимум, номер, с которого продолжится
   нумерация. Вы сверяете её с бумажными журналами и подтверждаете либо правите
   любую строку вручную. Без подтверждения счётчики не включаются.
   Отдельной строкой в этой же таблице выводятся **пропуски в нумерации**
   (например, «ВИК: 1-186, отсутствуют 44, 45, 91»). Пропуск — это либо запись,
   потерянная при миграции, либо номер, аннулированный на бумаге; разбирается
   до запуска.
5. **Старый файл переводится в режим «только чтение»** и переносится в папку
   `Архив\До перехода\`. Не удаляется — но и не редактируется больше никогда.
6. Все рабочие места получают новую версию, проверяется обмен через общую папку.

Шаг 5 обязателен. Пока старый файл открыт на запись, в него будут писать по привычке.

### 19.4. Первая неделя

Первые дни номера выдаются как обычно, но раз в день мастер сверяет журнал с бумагой:
нет ли пропусков, все ли документы сформировались. Неделя такой сверки — и переход
можно считать состоявшимся.

Журналы за 2026 год в декабре печатаются **из новой системы**, целиком за год,
включая записи, сделанные до перехода.

# Приложение А. Полный перечень форм и журналов ЛНК и их статус

Сверка проведена по всем документам системы менеджмента: Правила проведения работ по
НК, Правила поверки и ТО средств НК, Правила учёта документации, Правила внутренних
проверок, Правила обратной связи и корректирующих действий, Правила рассмотрения
рекламаций, Руководство по менеджменту, Паспорт ЛНК.

**Комплект полный** — последний недостающий документ (Правила рассмотрения рекламаций,
Ред. 1) получен, его формы учтены.

Всего выявлено **34 формы**. В ТЗ до этой сверки было учтено 13, частично — 4,
не учтено — 17.

**Решение: в систему включаются все 34.** Причина простая — форма, оставленная
«ручным шаблоном Word», через год расходится с системой: в реестре СИ прибор списан,
а в отдельном файле он ещё числится, и никто этого не видит, пока не придёт проверка.
Ради этого стоит потратить время один раз.

Это влияет на сроки, но не на порядок работ. Неучтённые 17 форм распределяются по уже
намеченным этапам, а не образуют отдельный: журналы и реестры идут в этапы 1-2 вместе
с остальной структурой данных, формы поверки и ТО — в этап 7, формы внутренних
проверок и корректирующих действий — отдельной очередью после этапа 8. Новых
механизмов они не требуют: это те же реестры, те же печатные формы, тот же счётчик
номеров.

Три уточнения по объёму:
- **Технологические карты** — в системе живёт только учёт (номер, объект, метод, дата,
  кем разработана). Сам текст карты остаётся документом Word: он пишется под конкретную
  задачу, автоматизировать в нём нечего.
- **Формы, заполняемые от руки на объекте** (черновые записи при контроле) остаются
  бумажными по существу — в системе учитывается факт их наличия и место хранения.
- **Приложения к Паспорту**, дублирующие реестры, не заводятся отдельно: они собираются
  из тех же данных (раздел 10).

## А.7. Два дефекта в ваших документах, найденные при сверке

**1. Журнал учёта заключений имеет три разных номера приложения.** В Правилах
проведения работ он значится: в оглавлении — как Приложение №6, в тексте раздела 5 —
как «приложение № 12», а фактически размещён как Приложение №14. При этом Приложение
№12 в теле документа — это протокол теплового контроля. Найти форму по ссылке из текста
невозможно.

**2. Оглавление тех же Правил не соответствует телу документа.** В оглавлении шесть
приложений, в документе — четырнадцать: пункт «Форма отчётных документов» (№5 по
оглавлению) в теле развернулся в приложения с 5 по 13.

Ни то, ни другое на работу системы не влияет, но при аттестации к таким расхождениям
придираются, и поправить их дешевле сейчас, вместе с остальной актуализацией.
