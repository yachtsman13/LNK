# Система учёта и документооборота ЛНК — техническое задание

Версия проработки: 3 (Excel + VBA, мастер-ПК, обмен через сеть/флешку)
Статус: **проработка, к реализации не приступали**

Ветка Access закрыта — у сотрудников нет опыта работы с ним, порог входа выше пользы.
Материалы по ней остаются в папке `Access/` только как история анализа.

---

## 1. Что решаем

Три рабочих места, у каждого полный комплект локально. В общей папке — только обмен.
Сеть есть, но ненадёжная, поэтому всё должно продолжать работать без неё, а обмен —
уметь идти и через флешку без изменений в коде.

Требования, зафиксированные по ходу обсуждения:

| Требование | Как закрывается |
|---|---|
| Основные файлы на каждом рабочем месте | Локальные `.xlsm` + `.xlsx`, сеть не нужна для работы |
| В сети минимум | Счётчики, дельты, свод, версия — сотни килобайт |
| Обновление через сеть или флешку | Один механизм, отличается только корневой путь |
| Номера строго без пропусков | Единый счётчик + разделение «черновик / регистрация» |
| Актуальность в течение минут | Автосинхронизация по таймеру + при открытии/закрытии |
| Справочники правит каждый | Построчный обмен, слияние у мастера, отчёт о конфликтах |
| Учёт «кто где» | Отдельный реестр отсутствий + связь с планированием |
| Паспорт ЛНК из реестров | Сборка по кнопке, 6 разделов из 11 — прямые выгрузки (раздел 10) |
| Графики обслуживания оборудования | Реестр обслуживания + расчёт плана из периодичности (раздел 11) |
| Журнал выдачи оборудования | Реестр выдач со связью с «СИ» и проверками (раздел 12) |
| Печать журналов в конце года | Общий механизм для всех журналов (раздел 13) |

## 2. Состав файлов

### На каждом рабочем месте (локально)

```
D:\ЛНК\
├── ЛНК_Программа.xlsm     ← код, макросы, Меню, Дашборд, печатные формы
├── ЛНК_Данные.xlsx        ← журнал, справочники, кто-где, задачи
├── Шаблоны\               ← 8 шаблонов Word (#Плейсхолдеры)
└── Готовые\               ← сформированные акты и протоколы, по годам и методам
```

**Программа и данные разделены намеренно.** Обновление версии заменяет только
`ЛНК_Программа.xlsm`; `ЛНК_Данные.xlsx` не трогается никогда. Иначе любое обновление
затирало бы рабочие данные — это самая частая причина, по которой такие системы
перестают обновлять.

### В общей папке (сеть или флешка)

```
\\сервер\ЛНК_Обмен\   (или E:\ЛНК_Обмен\)
├── Счётчики\
│   ├── ВИК-2026.txt          ← одно число
│   ├── УЗТ-2026.txt
│   └── … по методу на каждый год
├── Входящие\
│   └── 20260901-1432-Матяш.csv    ← дельты от специалистов
├── Свод\
│   └── ЛНК_Свод.xlsx              ← публикует мастер
├── Конфликты\
│   └── Конфликты_20260901.csv     ← спорные правки для разбора
└── Версия\
    ├── версия.txt
    └── ЛНК_Программа.xlsm
```

Путь к общей папке — **настройка в книге, а не константа в коде**. Нет сети — макрос
предлагает выбрать путь к флешке, дальше всё работает так же.

## 3. Роли и мастер-ПК

- **Специалист** (любое рабочее место): вводит данные, формирует документы, отправляет
  дельты, получает свод.
- **Мастер** (одно рабочее место): дополнительно собирает дельты, разрешает конфликты,
  публикует свод.

Роль мастера — **переключаемая галочка в настройках книги**, не привязана к человеку
жёстко. Если мастер в отпуске — роль передаётся на время. Книга подсказывает об этом
сама: если мастер числится отсутствующим по реестру «Кто где», при запуске выводится
напоминание назначить временного.

Это цена варианта «мастер-ПК»: логика слияния пишется один раз вместо трёх, но пока
мастер не собрал свод, остальные видят данные на момент последнего свода.

## 4. Модель данных

### 4.1. Журнал — в вашем формате (одна строка = один объект контроля)

Возвращаемся к структуре, которая у вас уже работает: строка описывает **один объект
за одну дату**, применённые методы — колонками. Отдельные журналы по методам строятся
из этого листа для печати.

| Группа | Поля |
|---|---|
| Служебное | `ID записи` (например `М-2026-0147`: код ПК + год + счётчик), `Статус` (Черновик / Зарегистрирован), `Кем внесено`, `Изменено` |
| Общее | № п/п, Дата проведения контроля, Заказывающее подразделение, Наименование объекта контроля, Заводской / рег. № объекта |
| Учёт экземпляров | № экз. и дата передачи в архив ЛНК, № экз. / исходящий номер / дата отправки, Отправитель |
| По каждому методу (×8) | `<Метод>: №`, `<Метод>: исполнитель` — для ВИК, УЗД, УЗТ, АЭ, ТВ, ТК, ВД, МК |
| Прочее | Примечание |

Метод, который не применялся, остаётся пустым. Колонка исполнителя — выбор из
справочника специалистов, не свободный текст.

**Печатные журналы по методам.** Листы `Печать_ВИК`, `Печать_УЗТ` и т.д. **строятся
макросом заново** из основного листа, а не тянутся формулами ИНДЕКС/ПОИСКПОЗ.
Причина прямая: в вашем текущем файле такие формулы протянуты на 2000 строк, а в
колонке-подписи до сих пор стоит «2025» вместо «2026» — формулы этого не замечают,
потому что ищут по другому полю. Перестроение макросом убирает целый класс таких
ошибок и работает быстрее.

Состав печатного журнала: № п/п, регистрационный номер (`№-Год-Метод`), дата
регистрации, заказывающее подразделение, объект контроля (с заводским номером),
исполнитель, № экз. и дата в архив, № экз. / исходящий / дата отправки, отправитель,
примечание. Титульный лист — по вашему образцу, с учётным номером журнала.

### 4.2. Справочники

`СИ`, `Специалисты`, `НД`, `Инструктажи` — как в собранной книге v2, плюс **обязательное
поле `ID`** у каждой записи (`СИ-0012`, `СП-0003`). Без стабильного ID построчное
слияние невозможно: номер строки меняется, заводской номер могут поправить при
опечатке, ФИО пишут по-разному.

Правит любой сотрудник. Конфликты разбираются у мастера (раздел 6).

Состав полей расширяется под сборку Паспорта — реестры должны содержать всё, что
требует его форма, иначе документ соберётся с пробелами. Перечень дополнительных
полей для «СИ» и «Специалистов» — в разделе 10.3.

### 4.3. Кто где — новый реестр

| Поле | Содержание |
|---|---|
| ID | `КГ-0031` |
| ФИО | из справочника специалистов |
| Вид | Отпуск основной / Отпуск без сохранения / Больничный / Командировка / Выезд на измерения / Учёба, повышение квалификации / Отгул / Прочее |
| Дата с, Дата по | период |
| Основание | № приказа, ссылка на график отпусков |
| Доступен для работ | Да / Нет — подставляется по виду, можно переопределить вручную |
| Кем внесено, Изменено | автоматически |

Важное различие: **«выезд на измерения» — это не отсутствие**, человек работает.
Для планирования он занят, но документ по его работе оформлять можно. Поэтому вид
отсутствия и признак «доступен» разведены отдельными полями.

Отдельный лист **«График отпусков»** — плановый, на год: ФИО и периоды. По кнопке из
него создаются записи в «Кто где», чтобы не вносить одно и то же дважды.

### 4.4. Задачи и План-график

Без изменений относительно собранной книги v2, добавляется только проверка занятости
исполнителя (раздел 8).

## 5. Нумерация: черновик и регистрация

Строгая нумерация без пропусков возможна только при едином арбитре. Отсюда разделение:

| Этап | Номер | Нужна общая папка |
|---|---|---|
| Ввод результатов, формирование документа, проверка | `ЧЕРНОВИК-Матяш-007` | нет |
| **Регистрация в журнале** | `204-2026-ВИК` — выдаёт счётчик | **да, ~1 секунда** |
| Печать, сшив, передача в архив | уже с настоящим номером | нет |

Регистрация и так делается в лаборатории — там же, где печать и сшив. Выезд и
обработка результатов идут полностью автономно.

**Выдача номера** (в широком формате журнала — сразу на все отмеченные методы строки):
1. Макрос создаёт файл-блокировку `Счётчики\ВИК-2026.lock`. Если файл уже существует —
   значит, номер сейчас берёт кто-то другой; ждём и повторяем (до 5 секунд).
2. Читает число из `ВИК-2026.txt`, увеличивает, записывает обратно.
3. Удаляет блокировку.

Блокировка содержит метку времени и имя ПК: если книга упала, не сняв её, через
2 минуты она считается устаревшей и снимается автоматически, о чём пишется в журнал
операций.

Дополнительная страховка: при сборке свода мастер проверяет, что в пределах метода и
года нет двух записей с одним номером, и при совпадении выводит его в отчёт о
конфликтах. То есть даже теоретический сбой блокировки не пройдёт незамеченным.

**Флешка счётчики не обслуживает.** Два человека с разными флешками получили бы
одинаковые номера. Полностью офлайн — работа с черновыми номерами до появления сети.

## 6. Обмен и слияние

### 6.1. Формат дельты

Обычный CSV, одна строка = одна запись, разделитель `;`:

```
ТипЗаписи;ID;Действие;Автор;МеткаВремени;Поле1;Поле2;…
ЖУРНАЛ;М-2026-0147;ИЗМ;Матяш;2026-09-01T14:32:11;…
СИ;СИ-0012;ИЗМ;Сиволап;2026-09-01T14:35:02;…
КТОГДЕ;КГ-0031;НОВ;Бирюков;2026-09-01T15:01:44;…
```

Действия: `НОВ` (создана), `ИЗМ` (изменена), `УДЛ` (помечена удалённой — физически
записи не удаляются, чтобы удаление не «воскресало» при следующем слиянии).

### 6.2. Порядок

1. **Специалист → «Отправить мои изменения»**: всё, что изменилось с прошлой отправки,
   выгружается одним файлом во `Входящие\`.
2. **Мастер → «Собрать свод»**: читает все файлы из `Входящие\`, сортирует записи по
   метке времени, применяет к своей копии, публикует `Свод\ЛНК_Свод.xlsx` и, если были
   спорные правки, `Конфликты\Конфликты_ДАТА.csv`. Обработанные дельты переносятся в
   `Входящие\Обработано\`.
3. **Все → «Получить свод»**: локальные данные обновляются из свода.

Перед получением свода книга проверяет, есть ли неотправленные локальные правки, и
предлагает сначала отправить их — иначе они будут потеряны при обновлении.

### 6.3. Конфликты

- **Журнал**: конфликтов практически не бывает — записи добавляются, а номера уникальны
  по построению. Правка чужой зарегистрированной записи требует подтверждения.
- **Справочники**: если одну и ту же запись после прошлого свода правили двое,
  применяется более поздняя по времени, а **обе версии попадают в отчёт о конфликтах**.
  Молча ничего не теряется — мастер видит список и решает, надо ли поправить руками.

Для трёх человек, правящих справочники несколько раз в неделю, реальное пересечение
по одной и той же записи — редкость. Разбирать вручную придётся единичные случаи.

## 7. Синхронизация и работа без сети

- Автоматически при открытии книги и при закрытии.
- По таймеру каждые 10 минут — молча, если ничего нового.
- Кнопка «Синхронизировать» на Меню.
- Индикатор состояния на Меню: `Последняя синхронизация 14:32 ✓ сеть` /
  `⚠ Нет сети — работаем автономно, 3 изменения ждут отправки`.

Обрыв сети в момент обмена не портит данные: дельта либо доехала целиком, либо не
доехала и уйдёт в следующую синхронизацию. Файл свода публикуется через временное имя
с последующим переименованием — недописанный свод никто не прочитает.

## 8. Проверки перед действиями (эргономика)

Все проверки — **предупреждение с возможностью продолжить**, а не жёсткая блокировка.
Решение остаётся за человеком, но «не заметить» проблему нельзя.

| Действие | Что проверяется |
|---|---|
| Назначение исполнителя в План-график / Задачи / Журнал | Аттестован по этому методу на эту дату; не отсутствует по реестру «Кто где» |
| Формирование документа | Аттестация исполнителя действительна на дату контроля |
| Регистрация в журнале | Заполнены обязательные поля; номер получен через счётчик |
| Открытие книги | Просрочки по СИ, аттестациям, инструктажам, НД (уже реализовано на Дашборде) |

## 9. Формирование документов, печать, сшив

Переиспользуется всё, что уже собрано: 8 шаблонов Word с плейсхолдерами `#Поле` и
макрос подстановки.

Что автоматизируется:
- подстановка в шаблон данных из журнала и справочников;
- сборка документов одного объекта в один файл со сквозной нумерацией, без номера на
  первой странице, с пустым листом в конце под сшив;
- печать в 3 экземплярах, двусторонняя.

Что остаётся ручным — и это ограничение набора программ, а не недоработка:
свидетельства о поверке и удостоверения — сканы и PDF. Без Acrobat (есть только Reader)
и без прав на установку ПО их нельзя программно вставить в общий пронумерованный файл.
Печатаются из Reader отдельно и подкладываются в пакет по месту.

## 10. Формирование Паспорта ЛНК из реестров

### 10.1. Зачем

Шесть разделов Паспорта из одиннадцати — это таблицы, которые уже ведутся в реестрах.
Сейчас они живут в Паспорте отдельной копией и стареют: в присланной редакции №6 у
практически всех средств измерений с годовым циклом стоят даты поверки, истёкшие
в 2025 году. Пока Паспорт набирается руками, это будет повторяться.

Если Паспорт **собирается из реестров по кнопке**, устареть он не может в принципе,
а сама сборка становится проверкой: перед выпуском система показывает всё, что
просрочено или не заполнено.

### 10.2. Откуда берётся каждый раздел

| Раздел Паспорта | Источник |
|---|---|
| 1. Общие данные | Лист «Паспорт — постоянная часть» |
| 2. Профессиональная квалификация сотрудников | Реестры «Специалисты» + «Аттестации» |
| 3. Объекты неразрушающего контроля | Постоянная часть (область аттестации) |
| 4. Виды (методы) неразрушающего контроля | Постоянная часть (область аттестации) |
| 5. Оснащённость средствами НК | Реестр «СИ», раздел = «Средства НК», с группировкой по методу |
| 6. Меры, контрольные и настроечные образцы | Реестр «СИ», раздел = «Меры и образцы» |
| 7. Дозиметрические и радиометрические СИ | Реестр «СИ», раздел = «Дозиметрия» |
| 8. Вспомогательное оборудование | Реестр «СИ», раздел = «Вспомогательное» |
| 9. Перечень нормативных документов | Реестр «НД» |
| 10. Помещения | Постоянная часть |
| 11. Передвижные лаборатории | Постоянная часть |

Новый лист **«Паспорт — постоянная часть»** держит то, что меняется раз в несколько
лет: реквизиты, ответственные лица с телефонами, область аттестации, помещения,
номер редакции и дату. Заполняется один раз.

### 10.3. Что для этого нужно добавить в реестры

Разделы Паспорта содержат поля, которых в текущих реестрах нет. Их надо завести
**до** реализации, иначе сборка будет с пробелами.

**Реестр «СИ»:**

| Новое поле | Зачем |
|---|---|
| Раздел паспорта | Средства НК / Меры и образцы / Дозиметрия / Вспомогательное — определяет, в какой раздел попадёт запись |
| Метод контроля | Группировка внутри раздела 5 (ВИК, УЗТ, АЭ…) |
| Назначение | Колонка 3 Паспорта — что именно измеряет прибор |
| Технические и метрологические характеристики | Колонка 5 — диапазоны, погрешности; длинный текст |
| Владелец оборудования, основание владения | Колонка 6 |

**Реестр «Специалисты»:**

| Новое поле | Зачем |
|---|---|
| Основание привлечения | Трудовой договор / ГПХ / совместительство — колонка 3 Паспорта |
| Образование, повышение квалификации, стаж | Колонка 5 — длинный текст с перечнем программ обучения и датой начала стажа |
| Функции в ЛНК | Ответственный за метрологическое обеспечение, за фонд НД и т.д. — идёт в колонку 4 вместе с должностью |

Поля «Изготовитель», «Заводской №», «Год выпуска», «Дата ввода в эксплуатацию» в
реестре уже есть по отдельности — при сборке они склеиваются в одну ячейку Паспорта
в принятом там виде.

### 10.4. Как собирается

Технически это отличается от актов и протоколов: там таблицы фиксированной длины и
хватает замены `#Поля`, здесь количество строк заранее неизвестно.

Шаблон `Паспорт_ЛНК.docx` содержит постоянный текст и таблицы, в каждой из которых
**одна строка-образец** с маркерами. Макрос:

1. считает, сколько записей попадает в раздел;
2. дублирует строку-образец нужное число раз, сохраняя форматирование;
3. подставляет значения;
4. удаляет исходный образец;
5. в разделе 5 дополнительно вставляет подзаголовки по методам контроля.

### 10.5. Проверка перед выпуском

Перед сборкой выводится список того, что попадёт в документ некорректным:

- средства измерений с истёкшей поверкой или калибровкой;
- специалисты с истёкшей аттестацией;
- нормативные документы, не проходившие проверку на актуальность более года;
- незаполненные обязательные поля (назначение, характеристики, основание владения).

Выпуск можно продолжить с подтверждением — но «не заметить» уже нельзя. Именно этой
проверки не хватало, чтобы редакция №6 не ушла с просроченными датами.

### 10.6. Редакции

Номер редакции и дата хранятся в постоянной части. При сборке предлагается увеличить
номер; готовый файл сохраняется как `Готовые\Паспорт\Паспорт_ЛНК_Ред7_2026-09-01.docx`,
предыдущие редакции остаются на месте — история не затирается.

### 10.7. Смежное — стоит обсудить отдельно

Паспорт входит в комплект для аттестации лаборатории, а у самого **свидетельства об
аттестации ЛНК есть срок действия**. Сейчас он не отслеживается нигде, хотя это самый
дорогой по последствиям срок во всей системе: с его истечением лаборатория не может
работать вообще, в отличие от одного просроченного прибора. Добавить его на Дашборд
рядом с остальными сроками — работы на полчаса, если решите, что нужно.

## 11. Обслуживание оборудования: учёт и план-графики

### 11.1. Что требуют ваши Правила

«Правила организации и проведения поверки и технического обслуживания средств НК»
предусматривают две формы, которые надо уметь выпускать:

- **Приложение №6** — пятилетний план-график планово-предупредительных осмотров и ремонтов;
- **Приложение №7** — месячный план-график ППР.

Плюс карточка учёта средства НК (Приложение №1) содержит подтаблицу «Сведения о ремонте
и техническом обслуживании» — её тоже нужно чем-то наполнять.

### 11.2. Реестр «Обслуживание СИ» — факт выполненных работ

Одна строка = одно выполненное мероприятие. Из него же печатается подтаблица карточки
учёта, чтобы не вести одно и то же дважды.

| Поле | Содержание |
|---|---|
| ID | `ОБ-0045` |
| ID средства НК | ссылка на реестр «СИ» |
| Дата проведения | дата |
| Вид работ | ТО / Текущий ремонт / Средний ремонт / Внеплановое / Проверка после транспортировки |
| Содержание работ | текст |
| Исполнитель | свой сотрудник или сторонняя организация |
| Результат | Исправен / Неисправен / Выведен из эксплуатации |
| Трудозатраты, ч | для расчёта итогов план-графика |
| Израсходовано спирта, г | графа есть в вашей месячной форме |
| Основание | № договора, акта |
| Примечание | |

### 11.3. Что добавить в реестр «СИ» для планирования

| Новое поле | Зачем |
|---|---|
| Маркировка согласно схеме | Колонка 3 обеих форм |
| Группа обслуживания | Колонка 4 пятилетней формы |
| Единица измерения, Количество | Колонки 5-6 |
| Периодичность ТО / ТР / СР, мес. | Три отдельных поля — расчёт плана |
| Норма трудозатрат ТО / ТР / СР, ч | Графы норм и расчёт итогов по месяцам |

С учётом полей для Паспорта (раздел 10.3) реестр «СИ» становится широким — порядка
35 колонок. Редактировать такое построчно в листе неудобно, поэтому для него нужна
**карточка прибора**: отдельная форма, где одна запись показана вертикально, полями
сверху вниз. Ввод идёт через неё, лист остаётся для просмотра и фильтрации.

### 11.4. Как считается план

Дата следующего мероприятия = дата последнего мероприятия **того же вида** из реестра
«Обслуживание» + периодичность. Если мероприятие не проводилось ни разу — считается от
даты ввода в эксплуатацию.

Отметка в клетке месяца ставится тем приборам, у которых расчётная дата попадает в этот
месяц. Итоги трудозатрат по месяцу и по году — суммой норм по отмеченным работам.

### 11.5. Печатные формы

- **Пятилетний план-график ППР** (Прил.6) — строки приборы, колонки 5 лет × 12 месяцев
  плюс графы норм и итогов. Формируется на выбранный стартовый год.
- **Месячный план-график ППР** (Прил.7) — только приборы с мероприятиями в этом месяце,
  колонки дни 1-31 с отметкой «Р», графа расхода спирта, подписи исполнителя и
  принявшего работу.

Обе собираются той же техникой таблиц переменной длины, что и Паспорт (раздел 10.4).

### 11.6. Связь с Дашбордом

Ближайшие ТО и ремонты выводятся рядом с поверками — та же логика «просрочено /
истекает», отличается только источник срока.

### 11.7. Смежное — заявка на поверку на год

По вашим же Правилам заявки на поверку формируются на календарный год и направляются
в метрологическую службу, которая строит свой план-график. Заявка — это выборка из
реестра «СИ» тех приборов, у которых поверка истекает в планируемом году: тот же
механизм, отдельная кнопка. Скажите, нужна ли — добавлю в этап.

## 12. Журнал выдачи оборудования

### 12.1. Форма

Приложение №5 ваших Правил — «Журнал временной выдачи средств НК».

| Поле | Содержание |
|---|---|
| ID | `ВД-0112` |
| № п/п | в пределах года |
| Дата выдачи | дата |
| ID средства НК | **выбор из реестра «СИ»** — наименование, тип и зав. № подставляются сами |
| Назначение выдачи | Измерения / Поверка / Ремонт / Временная выдача в подразделение |
| Состояние при выдаче | Исправен / Неисправен |
| Кому выдано | из справочника специалистов либо текст для сторонних |
| Дата возврата | пусто, пока не вернули |
| Состояние при возврате | Исправен / Неисправен |
| Примечание | |

Графы подписей получившего и принявшего заполняются на распечатке — в электронной
таблице они не нужны, а на бумаге обязательны.

Прибор выбирается из реестра, а не вписывается текстом. Иначе через год половина
записей будет с разным написанием одного и того же прибора, и вопрос «где сейчас
толщиномер» останется без ответа.

### 12.2. Проверки при выдаче

- **Прибор уже числится выданным** и не возвращён — предупреждение с указанием, кому
  и с какой даты. Это основная причина, по которой приборы теряются.
- **Поверка просрочена, а назначение выдачи — «Измерения»** — предупреждение: измерять
  таким прибором нельзя. При выдаче на поверку или в ремонт просрочка нормальна, за
  этим прибор и выдают, поэтому там предупреждения быть не должно.
- **Прибор помечен неисправным**, а выдаётся на измерения — предупреждение.

### 12.3. На Дашборде

Плитка «Выдано и не возвращено» со списком по клику, и отдельно — «на поверке» и
«в ремонте». Это приборы, физически отсутствующие в лаборатории: при планировании
работ на неделю вперёд это надо видеть заранее, а не в день выезда.

## 13. Годовая печать и сшив журналов

По вашим Правилам журналы по завершении года распечатываются, прошиваются, визируются
подписями и сдаются в архив. Порядок одинаков для всех журналов, поэтому механизм
делается **один общий**, с выбором, что печатать:

- журнал учёта заключений — по каждому методу отдельно;
- журнал выдачи оборудования;
- журнал учёта инструктажей;
- журнал входного контроля средств НК — если решите вести и его, форма есть в
  Приложении №3 ваших Правил.

Что делает макрос «Печать журнала за год»:

1. отбирает записи выбранного журнала за указанный год;
2. формирует титульный лист по вашему образцу — наименование, год, учётный номер вида
   `00-2020.РЖ`, поля «Начат» и «Окончен»;
3. собирает таблицу с постраничной разбивкой и повторением шапки на каждой странице;
4. проставляет сквозную нумерацию, без номера на первой странице;
5. добавляет пустой лист в конце под бирку сшива;
6. отправляет на печать в нужном числе экземпляров.

Это тот же механизм, что уже спроектирован для пакета документов по акту (раздел 9) —
отличается только источником строк.

## 14. Обновление версии программы

В `Версия\версия.txt` — номер актуальной версии. Книга при открытии сравнивает со своей
и, если в общей папке новее, предлагает обновиться: копирует `ЛНК_Программа.xlsm` к себе
и перезапускается. `ЛНК_Данные.xlsx` не затрагивается.

Копирование — по подтверждению пользователя, а не автоматически: перезапись файла,
который может быть открыт, ломает больше, чем чинит.

## 15. Риски, которые надо держать в голове

1. **Мастер — единая точка.** В его отсутствие свод не собирается. Смягчение: роль
   переключаемая, книга напоминает назначить временного, если мастер отмечен
   отсутствующим.
2. **Last-write-wins в справочниках** может потерять одновременную правку. Смягчение:
   отчёт о конфликтах, обе версии сохраняются.
3. **Счётчики требуют общей папки** в момент регистрации. Смягчение: черновые номера
   до появления сети.
4. **Всё держится на макросах.** Подтверждено, что они работают, но при смене политики
   безопасности система встанет целиком.
5. **Excel — не база данных.** При 3 пользователях и нескольких тысячах строк в год
   запаса прочности достаточно. Ориентир, после которого стоит пересматривать
   архитектуру: 5+ одновременных пользователей или 20 000+ записей в журнале.

## 16. Порядок реализации

| Этап | Содержание | Результат |
|---|---|---|
| 1 | Журнал в широком формате + печатные журналы по методам макросом | Замена текущего плоского журнала, миграция 1001 записи обратно в широкий вид |
| 2 | Разделение программа/данные, настройки путей, ID у всех записей | Основа для обмена |
| 3 | Счётчики номеров, черновик → регистрация | Нумерация без пропусков |
| 4 | Обмен: отправка дельт, сбор свода у мастера, получение свода, конфликты | Совместная работа |
| 5 | Реестр «Кто где» + график отпусков + проверки занятости | Учёт присутствия |
| 6 | Расширение полей реестров + лист «Паспорт — постоянная часть» + сборка Паспорта | Паспорт по кнопке, всегда актуальный |
| 7 | Реестр «Обслуживание СИ», карточка прибора, пятилетний и месячный план-графики ППР | Обслуживание планируется, а не вспоминается |
| 8 | Журнал выдачи оборудования + проверки при выдаче + плитки на Дашборде | Видно, где находится каждый прибор |
| 9 | Общий механизм годовой печати журналов | Закрытие года по всем журналам одной процедурой |
| 10 | Обновление версий через общую папку | Сопровождение |

Этапы 1-2 имеют смысл только вместе; 3 и 4 можно проверять по отдельности; 5, 8 и 9
не зависят от остальных и могут делаться параллельно.

**Порядок работ стоит поменять относительно нумерации.** Все этапы, которые расширяют
состав полей реестров — 6 (Паспорт) и 7 (обслуживание) — дешевле сделать **до** того,
как реестры наполнят данными: дозаполнять полторы сотни записей задним числом дороже,
чем завести поля сразу. Если ближайшая переаттестация лаборатории не за горами,
этап 6 разумно поднять на второе место, а этап 7 — сразу за ним.

Этап 9 логично привязать к концу календарного года: до декабря он не нужен, а в декабре
понадобится сразу по всем журналам.
