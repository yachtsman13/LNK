# Календарь сроков, задачи, заметки, пульт — проработка (к версии после 3.84)

Запрос заказчика: улучшить календарь сроков; комментарии в задачах; типы
источников — Заметки, Мои задачи, Общие задачи, Работы по плану,
Внеплановые работы; заметки и проекты задач пишет любой пользователь;
возможно, объединить Пульт и Календарь сроков под названием «Пульт».
Пока **не делается** — ниже то, что есть сейчас, что предлагаю и что
нужно решить.

## 1. Что есть сейчас (по коду 3.84)

- **Календарь сроков** (`renderКалендарь`, `календарьДела`): день / неделя /
  месяц / квартал / год, отбор по ОДНОМУ источнику. Источников семь, они
  мелкие и технические: План-график, Задачи, ППР, Поверка, Аттестация,
  Специалисты (допуски), Лаборатория. Порядок дел на дату — план-график,
  задачи по приоритету, прочие сроки, ППР.
- **Пробел:** календарь показывает только дела, у которых срок попадает
  в открытый период. Задача со сроком в прошлом месяце, которую так и не
  сделали, в текущем месяце не видна вовсе — её видно только на пульте
  плиткой «просрочено» и в «Задачах».
- **Задачи** (`18_задачи.js`): ставит и правит только место начальника
  (`яНачальник`). Остальные места принимают, выполняют, переносят срок.
  «Своя» задача — по полю «Рабочее место исполнителя» (`мояЗадача`).
- **Комментарии в задачах уже есть**, но спрятаны: блок «Заметки по ходу
  работы», кнопка «+ Заметка» открывает окно браузера (`prompt`) на одну
  строку; хранится текст, дата (без времени) и код места; править и
  отвечать нельзя; новые не отмечаются.
- **Опасное место для обмена:** заметки лежат ВНУТРИ записи задачи. Если
  два места между обменами допишут по заметке к одной задаче, при обмене
  победит одна версия задачи, вторая заметка уйдёт в «Правки одной записи
  с двух мест» — то есть потеряется для глаз, хоть и не бесследно. Для
  комментариев, которые пишут все, это не годится (тот же довод, по
  которому замеры вибрации — отдельный реестр, а не список в карточке).
- **Пульт**: плитки, поверка приборов, ППР месяца, задачи, «Мои задачи»,
  работы по месяцам, записи по методам, последние записи, «Недавно правили».

## 2. Типы источников — предложение

Пять типов из запроса — это группы, по которым удобно смотреть. Внутри
каждого остаются нынешние подробные источники (по ним работают переход
к карточке и порядок дел на дату).

| Тип | Что входит | Кто создаёт |
|---|---|---|
| **Заметки** | новая сущность: текст, необязательный срок, «только мне» или «всем» | любое место |
| **Мои задачи** | задачи, где исполнитель — это место (как «Мои задачи» на пульте), плюс мои проекты задач | — |
| **Общие задачи** | остальные задачи лаборатории | начальник; проект — любой |
| **Работы по плану** | планы-графики ВД/ТК/НК, ППР, представление на поверку | из планов |
| **Внеплановые работы** | см. вопрос 4 | — |

Сроки, которые не «работа» (истечение поверки, аттестации, ПБ, допусков,
сроки лаборатории), в список заказчика не попали. Предлагаю шестой тип
**«Сроки»** — иначе их некуда отнести (вопрос 3).

В календаре: у каждого типа свой цвет-метка, отбор флажками (несколько
типов сразу, а не один источник), переключатель «только моё» (мои задачи
и мои заметки).

## 3. Заметки — новая сущность

- Пишет любое место. Поля: текст, срок (необязателен), видимость
  («только этому месту» / «всем местам»), «сделано».
- Видимость — по рабочему МЕСТУ, а не по человеку: программа не знает,
  кто сидит за компьютером (за одним местом бывают разные люди). Это
  стоит знать: «только мне» = «только этому компьютеру».
- Заметка «всем» ходит в обмене; «только мне» — нет (остаётся в памяти
  этого места и в его резервной копии).
- Заметку без срока видно в отдельном списке «Без срока» рядом с
  календарём; со сроком — в календаре в свой день.
- Из заметки одним нажатием — проект задачи (текст переносится).
- Свой реестр (`lnk_notes`), не задачи: у заметки нет приёма, проверки,
  отчёта, и в отчёт по задачам она не должна попадать.

## 4. Проекты задач — пишет любое место

- Новое состояние задачи **«проект»** перед «назначена». Любое место
  может завести проект: что сделать, подробно, предложить срок и
  исполнителя, приоритет.
- Автор правит свой проект, пока его не рассмотрели.
- Начальник видит «На рассмотрение: N» (плитка на пульте, отбор в
  «Задачах») и делает одно из трёх: **утвердить** (проект становится
  обычной назначенной задачей, срок и исполнитель — какие он поставит),
  **вернуть автору** с комментарием, **отклонить** с причиной.
- В отчёт по задачам проекты и отклонённые не идут; в календаре проект
  виден автору и начальнику с пометкой «проект».
- Проект с моим местом исполнителя — в «Мои задачи» с той же пометкой.

## 5. Комментарии в задачах

- Блок «Заметки по ходу работы» переименовать в **«Комментарии»**
  (слово «Заметки» займут заметки из п. 3, иначе путаница).
- Поле ввода прямо в задаче вместо окна браузера, несколько строк,
  Ctrl+Enter — отправить.
- У комментария: текст, дата и время, место, кто (выбор из специалистов,
  подставляется рабочее место специалиста, правится).
- **Отдельный реестр** (`lnk_task_comments`, комментарий — своя запись со
  ссылкой на задачу): два места, написавшие одновременно, после обмена
  увидят оба комментария. Нынешние заметки задач переносятся туда при
  загрузке, без потерь.
- **Новые комментарии**: место помнит, когда последний раз открывало
  задачу; в списке задач и в «Моих задачах» — значок «💬 2 новых».
- Комментарии есть и у проекта задачи (так начальник и автор обсуждают
  проект до утверждения).
- Удалять чужие нельзя; свои — предлагаю не удалять, а исправлять
  следующей строкой (история видна всем). Вопрос 6.

## 6. Календарь — улучшения

1. **Просроченное из прошлых периодов** — строкой «Просрочено ранее: N»
   над сеткой и в списке дел, а не только в своём месяце (сейчас его в
   календаре не видно).
2. Отбор по типам флажками + «только моё» (п. 2).
3. **Добавить из календаря**: щелчок по дню → «＋ заметка» /
   «＋ проект задачи» (начальнику — «＋ задача») на эту дату.
4. **Отметить прямо в календаре**: заметку — «сделано»; задачу — то же
   действие, что в задаче (принять, выполнить); работу ППР и
   плана-графика — тот же отметчик, что в плане. Сейчас за каждой
   отметкой надо идти в раздел.
5. Перенос срока перетаскиванием: заметки — сразу; задачи — открывает
   окно переноса с причиной (перенос задачи обязан сохранять первый
   срок и причину, иначе отчёт врёт).
6. Значок числа новых комментариев у задач в клетке дня.
7. Вид **«Список»** (повестка) — дела периода по дням, без сетки, удобно
   на неделю; и печать недели/дня (листом, чтобы раздать).
8. Нагрузка дня: число работ и сколько из них без исполнителя — для
   планирования (данные уже есть: подготовка работ, назначения ПГ).

## 7. Пульт + календарь → «Пульт»

Рекомендую объединить: сейчас то, что горит, разнесено по двум разделам,
и на пульте нет самих дат.

Предлагаемый вид нового «Пульта» сверху вниз:
1. Плашки обмена и переезда (как сейчас).
2. Плитки внимания: просрочено, сегодня, на этой неделе, мои задачи,
   на рассмотрение (начальнику), новые комментарии, поверка истекает.
3. **Календарь** (по умолчанию «неделя», переключатели день / неделя /
   месяц / квартал / год / список) и справа колонка: «Мои задачи»,
   «Заметки без срока».
4. Свёрнутые блоки «Сводка»: поверка приборов, ППР месяца, работы по
   месяцам, записи по методам, последние записи, недавно правили —
   открываются щелчком, состояние помнится.

Пункт меню «Календарь сроков» исчезает; кнопки, которые вели в
календарь (из «Подготовки работ», из задач), ведут на «Пульт». Ничего из
нынешнего пульта не теряется — уходит в «Сводку».

Минус: пульт тяжелее. Расчёт производных дел за месяц уже делается для
календаря и быстрый; за год — тоже приемлемо (проверю замером).

## 8. Порядок работ (если всё принять)

1. Комментарии отдельным реестром + перенос старых заметок; заметки;
   проекты задач и права. (Основа — без неё нечего показывать.)
2. Типы источников, отбор флажками, просроченное ранее, добавление и
   отметка из календаря.
3. Объединение с пультом, «Сводка», вид «Список» и печать.

## 9. Вопросы заказчику

1. **Заметки «только мне»** — достаточно «только этому рабочему месту»
   (программа не знает человека за компьютером)? Или нужна видимость
   по специалисту — тогда месту нужен выбор «кто я» при работе.
2. **«Мои задачи»** — по рабочему месту (как сейчас) или по выбранному
   специалисту?
3. **Сроки** (поверка, аттестация, ПБ, допуски, лаборатория) — отдельным
   типом «Сроки» или внутрь «Работ по плану»?
4. **Внеплановые работы** — что это у вас: заявка подразделения на
   работу вне плана-графика (тогда новая сущность «заявка»: объект,
   метод, подразделение, срок, исполнитель, по выполнении связывается с
   записью журнала и актом по дополнительной заявке)? Или записи журнала,
   которых нет в плане? Или задачи, поставленные вне плана?
5. **Проект задачи** утверждает только начальник? Может ли автор сразу
   предложить исполнителя и срок?
6. **Свои комментарии**: исправлять только новой строкой или разрешить
   правку/удаление своего комментария (например, в тот же день)?
7. **Объединение**: устраивает ли вид из п. 7, что точно оставить на
   виду, а что можно свернуть в «Сводку»?
