# Подключение макросов

Собрать готовый `.xlsm` с уже зашитыми макросами извне Windows нельзя — формат
хранит код в двоичном блоке, который создаёт только сам Excel. Поэтому модули
поставляются файлами, а книга-программа собирается один раз, руками, минут за
пятнадцать. Дальше она копируется на остальные рабочие места как обычный файл.

---

## Важно про кодировку

Импортируйте файлы **только из папки `Для_импорта`**. Они записаны в cp1251 —
той кодировке, в которой редактор VBA читает `.bas` на русской Windows.

Файлы в корне папки `Макросы` лежат в UTF-8: их удобно читать и сравнивать
версии, но редактор VBA превратит из них кириллицу в нечитаемый набор символов.
Причём молча: код просто не скомпилируется, а причина будет неочевидна.

Если после импорта в коде вместо русских слов видны «РїСЂРѕРІ…» — импортировали
не ту копию. Удалите модуль и импортируйте из `Для_импорта`.

---

## Шаг 1. Разложить файлы

Создайте на каждом рабочем месте папку и разложите так:

```
D:\ЛНК\
├── ЛНК_Программа.xlsm      ← создадите на шаге 2
├── ЛНК_Данные.xlsx         ← из папки «Реестры»
├── Шаблоны\                ← 8 файлов .docx из папки «Шаблоны»
├── Схемы\                  ← картинки схем контроля (создать)
├── Сканы\                  ← ЛНК\, Удостоверения\, Поверка\ (создать)
├── Готовые\                ← пустая, заполнится сама
└── Копии\                  ← пустая, заполнится сама
```

Программа и данные разделены намеренно: обновление версии заменяет только
`ЛНК_Программа.xlsm`, а `ЛНК_Данные.xlsx` не трогается никогда.

## Шаг 2. Создать книгу программы

1. Откройте Excel, создайте пустую книгу.
2. **Файл → Сохранить как**, тип файла — **Книга Excel с поддержкой макросов
   (*.xlsm)**, имя `ЛНК_Программа`, папка `D:\ЛНК\`.

Обычный `.xlsx` макросы не хранит: сохраните в него — и весь код пропадёт при
закрытии, без предупреждения.

## Шаг 3. Установить модули

### Способ первый — установщик (рекомендуется)

Не импортировать по одному, а поставить всё сразу:

1. **Alt + F11** — откроется редактор Visual Basic.
2. В дереве слева найдите `VBAProject (ЛНК_Программа.xlsm)`.
3. **File → Import File…** → выбрать из папки `Для_импорта` один файл,
   **`Установка.bas`**.
4. В редакторе VBA нажать **F5**, в списке выбрать `УстановитьВсё`, **Run**.
5. Программа спросит папку `Для_импорта` — путь туда же, где лежит и этот
   файл, — и сделает всё сама: импортирует остальные двадцать два модуля,
   вставит код листа «ЭтаКнига», построит пульт.

Модуль «Установка» после этого можно оставить в книге — он не мешает, а
пригодится ещё раз: когда пришлют исправленную папку `Для_импорта`, тем же
способом накатываются обновлённые модули разом, не разбирая руками, что
именно поменялось. Повторный запуск безопасен — существующий модуль с тем же
именем удаляется и ставится заново, старый код не задваивается.

**Нужна одна настройка**, включаемая один раз на компьютере и без прав
администратора — личная настройка Excel, не системная: **Файл → Параметры →
Центр управления безопасностью → Параметры центра управления безопасностью →
Параметры макросов → «Доверять доступ к объектной модели проектов VBA»**. Без
неё Excel не даёт программе трогать код самой себя, и установщик честно об
этом скажет, а не упадёт непонятной ошибкой.

Если этот флажок недоступен (запрещён политикой безопасности) — переходите
к способу второму, он не требует этой настройки вовсе.

### Способ второй — вручную, по одному файлу

Не работает установщик — импортируйте руками, файл за файлом.

1. **Alt + F11** → `VBAProject (ЛНК_Программа.xlsm)` → **File → Import File…**
   и по очереди выберите из папки `Для_импорта`:

   | Файл | Что делает |
   |---|---|
   | `modConfig.bas` | настройки, пути, поиск колонок по заголовку |
   | `modNumbers.bas` | счётчики регистрационных номеров |
   | `modChecks.bas` | проверки аттестаций, занятости, поверки |
   | `modJournal.bas` | новая запись, регистрация, аннулирование |
   | `modGenerate.bas` | формирование документов Word |
   | `modPrintJournals.bas` | печатные журналы по методам |
   | `modBackup.bas` | резервные копии, пересчёт счётчиков |
   | `modExchange.bas` | обмен дельтами, сборка свода у мастера |
   | `modMedia.bas` | привязка к штатной флешке по серийному номеру |
   | `modDashboard.bas` | плитки пульта: что требует внимания сегодня |
   | `modKit.bas` | применённые приборы и минимальный комплект на метод |
   | `modPlan.bas` | плановые и внеплановые работы, отчёт за период |
   | `modScans.bas` | сканы свидетельств и удостоверений в пакет |
   | `modPassport.bas` | сборка Паспорта ЛНК из реестров |
   | `modPPR.bas` | план-график ТО на месяц, заявка на поверку |
   | `modPackage.bas` | сборка и печать пакета документов, бирка |
   | `modIssue.bas` | выдача и возврат оборудования |
   | `modYearEnd.bas` | закрытие года: все журналы одной процедурой |
   | `modUpdate.bas` | обновление версии программы |
   | `modElectro.bas` | журнал электроинструмента по утверждённой форме |
   | `modCard.bas` | карточка объекта: паспорт вертикально |
   | `modMeasure.bas` | точки замеров и подстановка их в протоколы |
   | `modMenu.bas` | пульт: плитки, кнопки, обработчик нажатий |

   Порядок значения не имеет, но нужны все двадцать два: они ссылаются друг
   на друга. (`Установка.bas` сюда не входит — он нужен только способу первому.)

2. **Вставить код книги.** `ЭтаКнига_код.txt` — не модуль, а код объекта
   книги, его импортировать нельзя, только скопировать текст: в дереве слева
   `Microsoft Excel Objects` → двойной щелчок по **ЭтаКнига** (ThisWorkbook) →
   вставить содержимое файла в открывшееся окно справа.

   Этот код открывает книгу данных при запуске, пересобирает пульт и делает
   резервную копию при закрытии.

3. **Собрать пульт.** В редакторе VBA нажмите **F5**, в списке выберите
   `ПостроитьПульт`, **Run**. Появится лист «Меню» — это и есть пульт.

### Что на пульте

**Сверху — плитки:** что просрочено, что истекает, сколько черновиков ждёт
номеров, как идёт план месяца. Плитка появляется, только если по ней есть что
делать: пульт, на котором всегда всё зелёное, перестают читать через неделю.

**Ниже — кнопки,** разделами: ежедневная работа, печать сканов, оборудование,
отчёты, данные, обмен, служебное. Справа от каждой — строка о том, что она
делает.

Пульт пересобирается заново при каждом открытии книги и по кнопке **«Обновить
пульт»**: число плиток меняется день ото дня, поэтому кнопки начинаются с той
строки, где кончились плитки.

Кнопки — элементы управления формы, а не ActiveX: они переживают копирование
книги между машинами и не требуют ни ссылок на библиотеки, ни их регистрации.

## Шаг 4. Заполнить настройки

Откройте `ЛНК_Данные.xlsx`, лист **Настройки**:

- **Код рабочего места** — `ПК1` … `ПК6`. Обязательно, книга напомнит.
  Это внутренняя метка, в документах она не печатается; без неё две машины
  заведут записи с одинаковыми номерами, и при слиянии одна затрёт другую.
- **ФИО сотрудника** — подставляется в «Кем внесено».
- **Пути** — если разложили не в `D:\ЛНК\`, поправьте.
- **Общая папка обмена** — оставьте пустым, если сети пока нет: программа
  сама найдёт штатную флешку. Появится сеть — впишете путь, и он станет
  использоваться автоматически.

## Шаг 5. Проверить

1. Закройте и снова откройте `ЛНК_Программа.xlsm`. При открытии Excel спросит
   про макросы — **Включить содержимое**.
2. На пульте нажмите **Новая запись в журнале** → должна появиться
   черновая строка в журнале.
3. **Построить печатные журналы**, год 2026 → появятся листы `Печать_ВИК`,
   `Печать_УЗТ` и так далее с мигрированными записями.
4. **Сделать резервную копию** → в папке `Копии` появится файл с датой.

Если на шаге 2 выходит ошибка «Sub or Function not defined» — не импортирован
один из модулей. Если кнопка нажимается, но ничего не происходит — проверьте,
что модули импортированы из папки `Для_импорта`, а не из `Макросы`.

## Шаг 6. Разложить на остальные места

Скопируйте всю папку `D:\ЛНК\` на второе и третье рабочее место, на каждом
поправьте в настройках **код рабочего места** и **ФИО**. Импортировать модули
заново не нужно — они уже внутри `.xlsm`.

## Порядок заполнения журнала учёта заключений

### Что чем отмечается

В журнале одна строка — **один объект за одну дату**, а применённые методы стоят
колонками: у каждого метода две колонки, «№» и «исполнитель».

**Метод считается применённым, если по нему выбран исполнитель.** Колонка «№»
серая — туда номер впишет система при регистрации. Заполнять её руками не нужно
и не надо: пока номер не выдан счётчиком, он ничей.

Это же правило работает везде: по нему определяется, какие документы формировать,
что попадёт в печатный журнал и по каким методам выдавать номера.

### Два уровня: акт и объекты

**Акт — один на работу**, а объектов в работе обычно несколько. У акта своя серия
номеров (`АКТ 01-2026`), у каждого объекта внутри акта — свои номера протоколов по
методам. В журнале это выглядит так: несколько строк подряд с одним номером акта,
у каждой свой объект и свои номера методов.

Работа без акта тоже бывает — когда выпускается только протокол по одному методу.
Тогда колонка «№ акта» остаётся пустой, и это нормально.

### Шаг 1. Завести строки

Кнопкой **«Новая запись в журнале»** — по строке на каждый объект работы. Строка
появляется со статусом «Черновик», сегодняшней датой и вашим ID записи.

### Шаг 2. Заполнить синие колонки

| Колонка | Что вносить |
|---|---|
| Дата контроля | когда фактически проводили |
| Заказывающее подразделение | от кого работа |
| Объект контроля (выбор из справочника) | выбор из выпадающего списка: наименование, заводской и регистрационный номера в одной строке |
| Наименование объекта в документе | подставится из справочника; правьте, если при контроле название уточнилось |
| `<Метод>` исполнитель | по каждому применённому методу — выбор из справочника специалистов |
| № экз., дата в архив / исходящий | заполняется позже, при передаче |
| Отправитель | кто отправлял заказчику |

Серые колонки — «№ п/п», «Год», «ID объекта», «Заводской №», «Рег. № объекта»,
номера методов — не трогать: они считаются сами.

**Ничего не выбирается по ID.** Везде, где раньше нужно было вписать номер
записи или прибора, теперь выпадающий список из читаемых обозначений:

| Где | Что видно в списке |
|---|---|
| Объект в журнале | `Сосуд воздушный В-1,6, зав. № 4412, рег. № 18-3007` |
| Запись журнала на дочерних листах | `14.08.2026 · АКТ 07-2026 · Бак водоподъёмной установки  [МИГР-2026-0031]` |
| Средство НК | `Толщиномер ультразвуковой, УТ-301, зав. № 10924` |

Так же выбираются специалист на листах «Аттестации», «Кто где» и в графике
отпусков, прибор — в обслуживании, в журнале выдачи и в журнале
электроинструмента, объект и запись журнала — в плане-графике работ.

ID остаётся — по нему связаны листы, — но его подставляет формула в соседнюю
серую колонку. Запоминать и сверять цифры больше не нужно; в квадратных скобках
ID показан только для того, чтобы две одинаковые на вид записи можно было
различить.

### Шаг 3. Открыть акт

Выделите строки объектов, которые входят в одну работу, и кнопка **«Открыть новый
акт»**. Номер выдаст счётчик и проставит его сразу всем выделенным строкам.

Вписывать номер руками не нужно и не стоит: именно на ручном вписывании акты и
дублируются. Колонка «№ акта» серая по той же причине, что и колонки «№» методов.

### Шаг 4. Ввести замеры

Пока — по **УЗТ и ТВ**: только у них в шаблонах есть таблицы под точки
(24 и 16 полей). По остальным методам результат пишется текстом на листе
«Данные протоколов».

Кнопка **«Добавить точки замеров»**, указать сколько. Появятся строки на листе
«Замеры»:

- **УЗТ** — заполняете «Замер 1…5», минимум считается формулой;
- **ТВ** — заполняете «Твёрдость, МПа», НВ пересчитывается по таблице,
  снятой с вашего файла (162 пары, НВ от 100 до 500).

В шаблон попадают **первые четыре точки** — столько в нём мест. Точек можно
завести больше: они останутся в системе, а программа скажет, сколько не
поместилось, и предложит дописать их руками. Молча они не теряются.

Незанятые места в шаблоне очищаются: в готовом документе не останется
видимых `#Т3С1`.

### Шаг 5. Заполнить поля протокола

Лист **«Данные протоколов»**, одна строка на пару «запись + метод»: номер
наряда-заявки, применённые НД, результаты, выявленные дефекты, заключение,
рекомендации, два средства НК и руководитель работ. Для ВД и ТК там же
«Параметр 1/2» и «Условие 1/2» — в шаблонах этих методов поля названы
одинаково, поэтому колонки общие.

**Для АЭ — отдельный лист «Данные АЭ»**: двенадцать полей про настройку
аппаратуры и режим нагружения (преобразователи, усиление, полоса частот,
дискриминация, затухание, скорость нагружения, выдержки). В общий лист их
класть незачем — у остальных методов они пустуют.

От работы к работе эти настройки меняются мало, поэтому есть кнопка
**«Скопировать настройки АЭ»**: берёт их из последней заполненной работы по АЭ.
Уже заполненное не затирается — копируются только пустые поля, а дальше
правится то, что действительно изменилось.

Средства НК выбираются из списка по наименованию с заводским номером —
тип и срок поверки подставятся сами. В вашем прежнем шаблоне акта ВИК они были
вписаны текстом вместе с датами поверки, и эти даты устаревали незаметно.

В протокол помещаются **два** средства — столько мест в шаблоне. Комплект обычно
больше, поэтому его полный состав ведётся отдельно, см. следующий шаг.

### Шаг 5а. Отметить применённые приборы и проверить комплект

Кнопка **«Добавить применённые средства»**: указываете метод и сколько приборов
добавить, на листе «Применённые средства НК» появляются строки, в них выбираете
приборы из списка. Срок поверки и его статус подтягиваются сами; просроченная
поверка видна сразу, до формирования документа.

**Отмеченный прибор считается выданным.** Если им провели контроль, он к тому
моменту был у исполнителя на руках — вписывать тот же факт второй раз в журнал
выдачи не нужно: при регистрации записи строки заводятся сами, датой контроля,
на исполнителя метода, с основанием «Контроль по акту … , метод …».

Строка не появится, если прибор на эту дату **уже** числится выданным: выдача
на неделю выездных работ закрывает все её дни, а не плодит строку на каждый.
Если прибор на дату контроля числится за **другим** человеком, система об этом
скажет — это или ошибка в исполнителе, или прибор передали из рук в руки, не
отметив возврат.

Заводится строка выдачей и возвратом одним днём: работа выполнена, прибор в
лаборатории. Иначе через неделю пульт показывал бы полсотни «невозвращённых»
приборов, спокойно стоящих на месте, и на предупреждение про действительно
невозвращённый перестали бы смотреть. Прибор остаётся на руках — выдайте его
обычным порядком, тогда автоматическая строка уже не заведётся.

Для записей, заведённых раньше, и для правок задним числом есть кнопка
**«Отметить выдачу по применённым»**.

Кнопка **«Проверить комплект приборов»** сверяет отмеченное с листом
**«Минимальный комплект»** и называет, чего не хватает по каждому применённому
методу. Та же проверка идёт перед формированием документов — она не запрещает,
а спрашивает.

Лист «Минимальный комплект» описывает позицию не прибором, а признаком: не
«Толщиномер УТ-301 зав. № 10924», а «толщиномер». Прибор спишут и купят другой,
а требование останется. Проверка ищет признак в наименовании, типе и назначении
применённых приборов.

Лист заполнен предложением — по назначению приборов, чтобы проверка работала с
первого дня. **Колонка «Основание (НД, пункт)» намеренно пустая**: сверьте
позиции со своими технологическими картами, впишите пункт — и позиция станет
вашей, а не моей. Лишнее удалите, недостающее допишите; «Обязательно = Нет»
означает, что о позиции только напомнят.

### Шаг 6. Сформировать документы

Кнопка **«Сформировать документы»**. По каждому применённому методу создаётся
файл Word в папке «Готовые», год и метод разложены по подпапкам. Незаполненные
поля остаются `#Плейсхолдерами` — их дописывают в самом документе.

Перед формированием система проверит: действует ли аттестация исполнителя на дату
контроля, не числится ли он отсутствующим, нет ли просроченной поверки, отмечен ли
минимальный комплект приборов. Ни одна проверка не запрещает — показывает и
спрашивает.

#### Наборы шаблонов со вставленными схемами

Схемы контроля и картинки вставляются **в сам шаблон Word** — так они и
останутся картинками, а не будут собираться программой по точкам. Разные схемы —
разные файлы шаблонов:

```
Шаблоны\
├── Протокол_УЗТ.docx              ← общий, если своего варианта нет
├── Протокол_УЗТ__Сосуд.docx       ← со схемой точек по сосуду
├── Протокол_УЗТ__Баллон.docx      ← со схемой по баллону
└── Протокол_УЗТ__Трубопровод.docx
```

Имя варианта — после **двух** подчёркиваний. Система берёт вариант по **типу
объекта** из справочника; если файла с таким именем нет, берётся общий шаблон.
Чтобы добавить схему, достаточно положить в папку ещё один файл — код править
не нужно.

Если по конкретной работе нужен не тот вариант, что задан типом объекта,
впишите его имя в колонку **«Вариант шаблона»** на листе «Данные протоколов»:
заполненная клетка перебивает выбор по типу.

#### Второй способ: картинка вставляется в шаблон программой

Свой файл шаблона на каждую схему хорош, пока схем немного. Когда их
десятки, начинается другое: правку шапки надо повторить во всех файлах, и
рано или поздно где-то не повторят.

Поэтому есть второй способ, и он работает вместе с первым. Поставьте в шаблоне
плейсхолдер **`#Схема_контроля`** там, где должна быть схема, а сами картинки
сложите в папку схем (по умолчанию `D:\ЛНК\Схемы\`). Шаблон тогда один на
метод, а схем под него сколько угодно.

Какая картинка куда идёт — на листе **«Схемы контроля»**:

| Колонка | Что вносить |
|---|---|
| Метод | ВИК, УЗТ, … |
| Вариант (тип объекта) | пусто — схема для всех объектов этого метода |
| Файл схемы | имя файла в папке схем |
| Ширина рамки, см / Высота рамки, см | размер места под схему |
| Подпись под схемой | печатается под картинкой |

**Про «строго регламентированный размер».** Задаётся не размер картинки, а
размер **рамки**. Картинка вписывается в рамку целиком, с сохранением
пропорций: по ширине или по высоте — смотря что упирается первым. Поэтому схема
не может растянуть таблицу, сдвинуть текст или уехать на другую страницу, а
скан, снятый в другом разрешении, встанет так же, как предыдущий. Растянуть
картинку по рамке было бы проще, но схема с искажёнными пропорциями читается
хуже и выглядит небрежно.

Если строки в реестре нет, программа ищет файл по имени: сначала
`УЗТ__Баллон.png`, потом `УЗТ.png` — расширения png, jpg, jpeg, emf, wmf, tif,
bmp. Так что можно вообще не заполнять реестр, а просто класть файлы с
правильными именами; реестр нужен, когда размер рамки или подпись должны
отличаться от общих.

Не нашлось ни строки, ни файла — `#Схема_контроля` останется в документе
видимым, как и любой другой незаполненный плейсхолдер. Это не молчаливая
потеря: место под схему видно.

### Шаг 7. Зарегистрировать

Когда работа готова — кнопка **«Зарегистрировать запись»**. Номера выдаются сразу по
всем применённым методам строки, статус меняется на «Зарегистрирован».

Пока сети нет, номера выдаёт флешка. Если её нет под рукой — записи спокойно
живут черновиками, а когда носитель придёт, нажимаете **«Зарегистрировать все
черновики»** и номера выдаются разом по всему накопившемуся.

### Шаг 7а. Отметить выполнение по плану

Кнопка **«Отметить выполнение по плану»** ищет на листе «План-график работ»
незакрытую строку по тому же объекту, не позже месяца контроля, и отмечает её
выполненной: проставляет фактическую дату и привязывает к записи журнала.

После этого в журнале колонка **«Вид работ»** сама показывает «По плану».
Ставить это руками нельзя и не нужно: галочка, которую ставит человек, рано или
поздно оказывается там, где плана не было, а вопрос «сколько мы сделали сверх
плана» задают именно тогда, когда галочкам уже не верят.

Не нашлось строки плана — работа так и останется внеплановой, и это нормально:
внеплановые работы бывают. Программа скажет об этом прямо.

Сколько сделано из плана месяца и сколько было сверх него — видно на пульте
плиткой «План работ», а за месяц или год — кнопкой **«Отчёт: план и
внеплановые»**.

### Шаг 8. Напечатать пакет

Встаньте на любую строку акта и нажмите **«Напечатать пакет»**. Собирается
**весь акт**: протоколы по всем его объектам в порядке методов, сканы
свидетельств, пустой лист для сшива, три экземпляра, бирка с числом листов
прописью.

Если у строки нет номера акта, печатается пакет по ней одной.

#### Сканы свидетельств — внутри пакета, а не мимо него

Раньше это была единственная неустранимая ручная операция: сканы печатались
отдельно и вкладывались руками, поэтому в сквозную нумерацию не попадали.
Устранимая её часть — картинки. Скан в **JPG, PNG или TIFF** Word вставляет сам,
и страницы со сканами становятся обычными страницами пакета.

Разложите сканы по папкам (путь задаётся в настройках, по умолчанию
`D:\ЛНК\Сканы\`):

```
Сканы\
├── ЛНК\              ← свидетельства и аттестат лаборатории: берутся все
├── Удостоверения\    ← квалификационные удостоверения специалистов
└── Поверка\          ← свидетельства о поверке приборов
```

**В имени файла должен быть заводской номер прибора или фамилия специалиста** —
по ним и ищется. Точного имени не требуется: `Поверка УТ-301 зав 10924 до
2027.jpg` найдётся по «10924».

В пакет попадают: свидетельства лаборатории → удостоверения исполнителей этого
акта → свидетельства о поверке приборов, применённых в этом акте. Каждый раздел
начинается с новой страницы, **по 4 скана на лист** (сетка 2×2; число меняется
настройкой «Сканов на страницу»).

Картинки кладутся в таблицу с точно заданной высотой строк и вписываются в
ячейку с сохранением пропорций. Поэтому четвёртый скан не съезжает на следующую
страницу из-за того, что второй оказался на сантиметр выше, а свидетельство не
выглядит растянутым.

Те же сканы можно напечатать отдельно, без пакета: кнопки **«Печать
свидетельств о поверке»** и **«Печать удостоверений»** на строке акта.

**Сканы в PDF** (сканируют по-разному — часть в JPG, часть в PDF, это нормально)
Word вставить как картинку не может, но раз в лаборатории стоит Acrobat, а не
только Reader, программа сама объединяет их через него — тем же признаком
(заводской номер, фамилия), в те же три раздела и в том же порядке — в один
файл `Сканы_PDF_….pdf` в папке «Готовые». Сколько в нём страниц, программа
узнаёт у Acrobat сама, спрашивать вас не будет.

**Что по-прежнему вручную** — распечатать этот объединённый файл (тоже 3 экз.,
двусторонне) и вложить между протоколами и пустым листом. Внутрь общей
нумерации пакета он не входит: поставить на уже готовый PDF номер по правилу
«лист, а не страница» можно только через JavaScript Acrobat, а такие вызовы
из автоматизации Acrobat разрешены не всегда — зависит от версии и настроек
безопасности конкретной машины. Рисковать этим ради строк на скане чужого
свидетельства мы не стали.

Если Acrobat не найден или файл не открылся (испорченный скан, не настоящий
PDF, несмотря на расширение) — программа честно говорит об этом и просит
посчитать листы руками, как раньше; ни один плохой файл не срывает всю сборку,
он просто пропускается со своим предупреждением. Если сканер умеет отдавать
JPEG — переключите его, и вручную вкладывать не придётся вообще ничего.

#### Нумерация: номер на лист, а не на страницу

При двусторонней печати лист бумаги несёт две страницы, а номер у него один.
Поэтому номер ставится **только на лицевых сторонах** и считает листы:
страницы 1, 3, 5 получают номера 1, 2, 3. На первом листе номера нет.

Так пакет нумеруется по умолчанию. Обычную сквозную нумерацию страниц можно
вернуть настройкой **«Нумеровать» = Страницы**.

Считает это поле Word `{=INT((PAGE+1)/2)}` — поле внутри поля. Собрать его из
макроса одной строкой нельзя, поэтому программа собирает его в два приёма и
**проверяет результат**: если Word поле не принял, пакет нумеруется по
страницам и об этом говорится вслух. Молча напечатать три экземпляра не с той
нумерацией хуже, чем сказать.

Двусторонний режим включается в свойствах принтера — из макроса им управлять
нельзя, это настройка драйвера.

### Шаг 9. Отметить движение экземпляров

По факту передачи заполняются «№ экз., дата в архив ЛНК», «№ экз., исходящий,
дата отправки», «Отправитель». Эти колонки идут прямо в печатный журнал.

### Порядок строк

Строки добавляются в конец, в порядке дат. Сортировать журнал вручную не нужно:
печатный журнал по методу сортируется по номеру сам.

## Почему печатные журналы могут не сформироваться

Если по кнопке **«Построить печатные журналы»** ничего не появилось — причина
почти всегда одна из трёх, и программа теперь сама называет их в сообщении.

**1. Не указан исполнитель.** Метод отмечается исполнителем. Если в строке
заполнены только дата и объект, система считает, что методов не применялось —
такая строка в журнал не попадёт и номеров не получит.

**2. Не тот год.** Отбор идёт по колонке «Дата контроля». Спросили 2026, а записи
датированы 2025 — журнал будет пуст.

**3. Смотрите не в той книге.** Листы «Печать_ВИК», «Печать_УЗТ» и прочие
создаются в книге **программы** (`ЛНК_Программа.xlsm`), внизу, а не в книге
данных. Данные читаются из `ЛНК_Данные.xlsx`, результат кладётся рядом с
макросами.

Незарегистрированные записи в журнал попадают, но помечаются: в графе
«Регистрационный номер» стоит «не зарегистрирован», в примечании — «ЧЕРНОВИК».
Их видно, чтобы перед печатью годового журнала не забыть зарегистрировать.
Сообщение после построения отдельно сообщает, сколько их.

## Как заменить модули на исправленные

Импортировать поверх существующего нельзя: редактор VBA создаст рядом второй
модуль с именем вида `modConfig1`, и работать будет старый.

Порядок замены:

1. **Alt + F11**, в дереве слева правый щелчок по модулю → **Remove modConfig**
   → на вопрос «Экспортировать перед удалением?» ответить **Нет**.
2. Повторить для всех модулей, которые заменяются.
3. **File → Import File…** и выбрать новые из папки `Для_импорта`.

Код листа «Меню» и «ЭтаКнига» удалять не нужно — он вставляется текстом, его
просто заменяют содержимым новых `.txt`, если те изменились.

Проще всего удалить все модули разом и импортировать заново: данные лежат в
отдельном файле и от этого не страдают.

## Как работает обмен

**Отправка.** «Отправить мои изменения» сравнивает книгу данных со снимком,
сделанным при прошлой отправке, и выгружает во «Входящие» только изменившиеся
строки. Сравнение со снимком, а не отметка «Изменено», выбрано намеренно:
книгу данных можно открыть и без программы, и тогда никакая отметка не
проставится, а снимок ловит любую правку.

**Сборка свода** — действие мастера. Перед применением дельт текущий свод
уходит в `Свод\История` — если слияние пройдёт неудачно, есть точное состояние
«до». Дальше дельты применяются, обработанные переезжают в `Обработанные\ГГГГ-ММ`
и **не удаляются**: их набор — полная история изменений и запасной путь
восстановления данных.

**Спорные правки.** Если строку правили и у вас, и у отправителя, побеждает
более поздняя по времени правки, а **обе версии попадают в отчёт**
`Конфликты\Конфликты_ДАТА.csv`. Молча ничего не теряется.

**Дубли номеров.** После слияния мастер отдельно проверяет, нет ли в пределах
метода и года двух записей с одним номером. Даже теоретический сбой блокировки
счётчика не пройдёт незамеченным.

**Расчётные колонки не переносятся.** Если у получателя в ячейке формула, дельта
её не трогает. Иначе первое же слияние затёрло бы формулы значениями.

**Строка без ID в обмен не попадает** — слияние опознаёт строки только по ID.
Поэтому перед отправкой всё заполненное, но безымянное, его получает
автоматически, и программа об этом сообщает.

### Получение свода

Автоматической замены открытого файла здесь нет: перезапись книги, которая
сейчас открыта, ломает больше, чем чинит. Программа проверит, нет ли у вас
неотправленных изменений, и покажет, что и куда скопировать.

### Флешка

«Зарегистрировать носитель» — действие мастера. Флешка опознаётся по серийному
номеру тома: скопировать папку на другую флешку можно, серийный номер — нет.

Регистрировать нужно **два** носителя: основной и резервный у мастера. С одним
единственным потерянная или умершая флешка останавливает обмен целиком.

Честно про границы: без прав администратора запретить подключение других флешек
нельзя — это делается политиками Windows. Проверка работает на уровне программы
и защищает от ошибки («я думал, эта тоже подойдёт»), а не от намерения.

## Паспорт и план-графики

### Паспорт ЛНК

Из одиннадцати разделов **шесть собираются из данных**: разделы 2 и 5-9 — это
реестры специалистов, аттестаций, СИ и НД. Остальные пять берутся с листа
«Паспорт_постоянная».

Перед сборкой проверяется, заполнено ли обязательное. Если нет — Паспорт **не
собирается**, а показывается список того, чего не хватает, с указанием строки.
Документ с пустыми местами хуже несобранного: пустоту в нём замечают не сразу,
а он идёт в комплект для аттестации лаборатории.

Просроченная поверка в разделах 5-8 не прячется, а помечается красным. Она
всё равно вскроется при проверке — лучше увидеть это заранее.

**Собирается в Excel, а не в Word.** Паспорт — почти сплошные таблицы
переменной длины, в Excel они получаются точнее. Если нужно попасть в
оформление действующей редакции слово в слово — пришлите её файлом, переделаю
на подстановку в шаблон Word.

Первую собранную редакцию стоит один раз сверить с действующей глазами:
опечатка в постоянной части иначе уедет во все следующие редакции.

### План-график ТО на месяц

Считается от **последнего фактически выполненного** обслуживания той же
категории плюс интервал. Если обслуживание не проводилось ни разу, план
считается от начала месяца, а строка помечается красным.

Просроченное показывается **один раз в начале месяца**, а не всей пропущенной
серией: план должен быть выполнимым, иначе его перестают открывать.

ТО-1 считается по рабочим дням — суббота и воскресенье пропускаются.

### Заявка на поверку

Приборы со сроком внутри выбранного года, отсортированные по кварталам —
так заявка сразу читается как график. Приборы с незаполненной датой поверки
**не выпадают молча**: они перечисляются отдельным списком в конце.

### Пересчёт пятилетнего плана

Действующий график 605-2025.ПЛ подписан и переносится как есть. Пересчёт по
периодичности даст другие числа — декадному ТО, например, 36 операций в год
вместо ваших 32. Поэтому пересчёт вынесен в отдельную кнопку с
предупреждением: он для НОВОГО пятилетнего графика, а не для действующего.

## Печать пакета документов

Порядок в пакете задан и не меняется: **акт → протоколы → свидетельства
лаборатории → квалификационные удостоверения → свидетельства о поверке →
пустой лист для сшива**.

Что делает макрос: находит в папке «Готовые» документы Word по всем методам
строки, собирает сканы-картинки в том же порядке, склеивает всё в один файл с
разрывами страниц, добавляет в конец абсолютно пустой лист, проставляет
нумерацию (**по листам, на первом листе номера нет**) и печатает три
экземпляра. Каждый экземпляр нумеруется заново — поэтому печатаются копии
одного документа, а не три склеенных подряд.

**Нумерация по листам.** При двусторонней печати номер стоит на лицевой стороне
и считает листы, а не страницы: страницы 1, 3, 5 получают номера 1, 2, 3.
Переключается настройкой «Нумеровать» — «Листы» или «Страницы». Подробнее — в
разделе про печать пакета выше.

**Бирка.** Число листов, вкладываемых вручную, макрос в обычном случае узнаёт
сам — у объединённого Acrobat PDF-файла есть число страниц, спрашивать вас не
нужно. Спросит, только если объединение не удалось (нет Acrobat, повреждён
скан) — тогда считать приходится по старинке. Складывает это число с листами
свода и печатает бирку с числом листов цифрами и прописью, с правильным
склонением: «27 (двадцать семь) листов», «21 (двадцать один) лист», «23
(двадцать три) листа». Прописью это чаще всего и пишут с ошибкой. Свой текст
бирки задаётся в настройках, подстановки `#ЧИСЛО`, `#ПРОПИСЬЮ`, `#ЛИСТОВ`,
`#ОБЪЕКТ`.

**Двусторонняя печать** включается в свойствах принтера. Из макроса ею
управлять нельзя: Word не даёт такого параметра, это настройка драйвера.
Поставьте двусторонний режим по умолчанию — тогда он применится ко всему.

**Что осталось вручную.** Сканы-картинки (JPG, PNG, TIFF) вставляются в пакет
и нумеруются вместе со всем остальным — с ними делать вручную нечего. PDF-сканы
Word вставить как картинку не может; их вместо этого объединяет через Acrobat
одна процедура на весь акт (см. «Сканы свидетельств» выше) — результат
печатается и вкладывается отдельным блоком, не в общей нумерации пакета:
проставить на уже готовом PDF номер «по листам» программно можно только
через JavaScript Acrobat, а такие вызовы разрешены не на каждой машине и не в
каждой версии — рисковать этим не стали. Если объединение не удалось (нет
Acrobat, битый скан), листы вкладываются по одному, как и раньше.

## Выдача оборудования

Прибор выбирается **курсором** по строке реестра СИ или, при заполнении журнала
руками, из выпадающего списка «Средство НК (выбор)» — наименование, тип и
заводской номер в одной строке. ID, наименование и заводской № в журнале выдачи
считаются формулами.

Строки по работам НК заводятся сами — см. «Шаг 5а» выше. Кнопка «Выдать
оборудование» остаётся для всего остального: прибор берут на обслуживание, на
поверку, в командировку — то есть тогда, когда работа по НК его не объясняет.

Перед выдачей проверяется: не выдан ли прибор уже (и кому), не списан ли, не
в ремонте, в порядке ли поверка. Ни одна проверка не запрещает выдачу — решает
человек, но осознанно.

При выдаче прибор помечается в реестре как «Выдан», при возврате возвращается
в «В работе». Пока возврат не отмечен, прибор виден на пульте.

## Закрытие года

Одна кнопка строит титульные листы, журналы по всем методам, листы заверения
и общую опись. В декабре журналы закрываются все сразу, и делать это по одному —

Лист заверения начинается с новой страницы: подпись не должна попасть на один

**после печати** — до неё оно неизвестно.

## Обновление версии

**Мастер** нажимает «Опубликовать версию»: программа копируется в общую папку,
рядом пишется `версия.txt` с номером, датой, автором и контрольной суммой
SHA-256.

**Остальные** при запуске получают предложение обновиться, если в общей папке
версия новее. Файл сначала копируется во временный, проверяется по контрольной
сумме и только потом ставится. Не совпала — обновление отменяется, старая
версия остаётся на месте и работать можно.

Контрольную сумму считает штатный `certutil` — он есть в Windows и прав
администратора не требует. Проверка ловит и оборвавшееся копирование по
нестабильной сети, и подменённый файл.

Заменить книгу, которая сейчас открыта, Excel не может, поэтому последний шаг
делается руками: закрыть Excel, удалить старый файл, переименовать
`~обновление.xlsm`. Предыдущая версия сохраняется в папке «Версии» — откат это
переименование файла, а не восстановление из копии.

`ЛНК_Данные.xlsx` при обновлении не трогается никогда. Затирание рабочих данных
обновлением — самая частая причина, по которой такие системы перестают
обновлять.

## Работа без сети, на флешке

Сеть для счётчика не нужна — нужен **единственный арбитр**, тот, кто хранит текущее
число. Одна назначенная флешка справляется с этим не хуже сетевой папки: она
физически одна.

### Настройка, один раз

1. На любом рабочем месте: **Подготовить флешку для обмена**. Создаётся структура
   `ЛНК_Обмен` с папками счётчиков, входящих, свода; флешка запоминается по
   серийному номеру тома. Данные на флешке не стираются.
2. На остальных рабочих местах, подключив **эту же** флешку: **Зарегистрировать
   носитель**.
3. Настройку «Общая папка обмена» оставить пустой. Режим обмена — «Авто».

Всё. Буква диска роли не играет: `E:` сегодня, `F:` завтра — программа ищет флешку
по серийному номеру.

### Как это выглядит в работе

Записи заводятся черновиками и живут так, сколько нужно: документы по ним
формируются, печатаются на проверку. Номеров у них ещё нет — в бумажный журнал они
не идут.

Флешка приходит к вам — нажимаете **«Зарегистрировать все черновики»**. Номера
выдаются разом по всем накопившимся записям. Записи, где чего-то не хватает (нет
исполнителя, объекта, даты), пропускаются и перечисляются в конце с причиной.

Флешки нет под рукой — на пульте висит плитка «Общая папка недоступна» с
пояснением, что именно не работает. Работать при этом можно, нельзя только выдавать
номера.

### Что даёт реестр выданных номеров

Каждый выданный номер дописывается в `Счётчики\Выданные-ВИК-2026.csv`: номер,
рабочее место, сотрудник, время. Файл счётчика хранит только последнее число, реестр —
всю историю.

Пока сети нет, книги на трёх машинах живут порознь, и это единственное место, где
видна вся выданная нумерация сразу. По нему же счётчик восстанавливается, если файл
счётчика потеряется.

### Когда появится сеть

Вписать путь в настройку «Общая папка обмена» на каждом рабочем месте и один раз
скопировать содержимое `ЛНК_Обмен` с флешки в сетевую папку. Дальше программа
переключится сама: сеть проверяется первой, флешка остаётся запасным вариантом на
случай, если сеть отвалится.

Переделывать ничего не придётся — структура папок одна и та же.

### Чего это не даёт

Свежести данных «в минутах». Пока свод не собран, каждый видит свою книгу. С сетью
свод собирается когда угодно, с флешкой — когда она дойдёт до мастера. На нумерацию
это не влияет: номера уникальны в любом случае, потому что арбитр один.

## Журнал электроинструмента

Форма утверждённая, не наша: 16 граф по Приложению 4 к РД 34.03.204. На рабочем
листе «Электроинструмент» они идут первыми и ровно в том порядке, что в форме.
Дальше — служебные колонки системы: связь с реестром СИ, класс защиты,
периодичность, срок, статус. **В печать выходят только 16 официальных граф**,
служебные остаются на рабочем листе.

**Дата следующей проверки не вводится руками** — считается от даты последней плюс
периодичность (по умолчанию 6 месяцев). Именно на ручном вводе такие журналы и
разъезжаются: дату проверки поставили, дату следующей забыли.

**На пульте** электроинструмент идёт отдельной плиткой с более короткими
порогами, чем поверка приборов: при полугодовой периодичности месяц запаса — это
уже много. Инструмент, у которого проверка не отмечена ни разу, считается
просроченным и попадает в ту же плитку: молчать о нём нельзя, работать им нельзя.

### Что проверить в форме

Первоисточник открыть не удалось — правовые сайты закрыты сетевой политикой той
среды, где я работаю. Состав граф собран по нескольким согласующимся описаниям
формы и совпадает с общеизвестным: наименование, инвентарный номер, дата и причина
проверки, испытание изоляции повышенным напряжением, измерение сопротивления
изоляции, проверка цепи заземления, внешний осмотр и работа на холостом ходу,
заключение, дата следующей проверки, кто проводил.

**Сверьте с вашей утверждённой формой.** Если графа названа иначе или их другое
число — поправьте заголовки прямо на листе: макрос печати берёт их оттуда, а не
из кода, и переделывать ничего не придётся. Только не меняйте порядок первых
шестнадцати колонок — печать опирается на него.

## Паспорт объекта и карточка

Паспортные данные — изготовитель, номер паспорта, марка материала, толщины,
диаметры, давления, среда, магнитные свойства и прочее — лежат **в справочнике
объектов** и заполняются один раз на объект. Дальше они подставляются во все
протоколы по нему.

Заполнять два десятка полей построчно в таблице неудобно: строка не помещается
на экран. Поэтому есть кнопка **«Карточка объекта»**: тот же объект показан
вертикально, полями сверху вниз, с подсказкой у каждого — куда оно попадёт в
документе. Поправили — **Сохранить карточку**.

Открывается карточка со строки журнала или со строки справочника объектов, на
которой стоит курсор.

### Если по этой работе значение другое

Колонка **«Переопределения паспорта»** на листе «Данные протоколов», в виде
`Поле=Значение; Поле=Значение`. Например `Рабочее давление=8,0 МПа`.

Переопределение действует только на этот документ. Справочник остаётся историей
объекта, а не одной работы — иначе прошлогодние протоколы задним числом
изменили бы смысл.

### Как имена полей связаны с шаблоном

Заголовок колонки превращается в имя плейсхолдера: «Марка материала» →
`#Марка_материала`. Отдельной таблицы соответствия нет намеренно — её пришлось
бы править при каждом новом поле. Добавили колонку в справочник объектов,
назвали её точно как плейсхолдер в шаблоне — она начала подставляться, менять
код не нужно.

### Что проверяется

`scripts/check_templates.py` сверяет все плейсхолдеры всех шаблонов с
источниками подстановки. Сейчас: **226 плейсхолдеров, без источника 0.**
Закрыты все восемь шаблонов целиком.

Не в счёт только места под схемы и графики — они вставляются вручную по
существу дела, картинку подставить неоткуда.

Плейсхолдер, которому неоткуда взяться, останется в готовом документе видимым
`#Заключение`. Проверка находит такие места до печати, а не у заказчика.
