# Система ЛНК — постоянные правила проекта

## Язык
**Всё общение с заказчиком — только по-русски.** Ответы, пояснения,
сообщения об ошибках. В коде и документации проекта — тоже русский:
имена функций, переменных, комментариев уже написаны так, продолжать так же.

## Условия у заказчика (не меняются)
- Прав администратора нет. Ставить ничего нельзя, portable-программы можно.
- Сети между рабочими местами нет — обмен только файлами (флешка, общая папка).
- Office 2016, AutoCAD, Acrobat. Windows 11.
- Рабочих мест 3, в перспективе 6.

## Как устроена программа
`Приложение/ЛНК.html` — один самодостаточный файл, открывается с диска или
флешки, без установки и без сети. Собирается скриптом:

    python3 scripts/export_json.py   # книга Excel  → Приложение/данные.json
    python3 scripts/build_app.py     # шаблон+данные → Приложение/ЛНК.html

**Править только `Приложение/шаблон.html`**, потом пересобирать.
`ЛНК.html` — сборка, руками не трогать.

Данные живут в памяти браузера (localStorage). Ключи **без номера версии** —
иначе новая версия программы откроется пустой.

Замерено: предел localStorage ~5 МБ, занято 235 КБ на 315 записей со
справочниками (~766 символов на запись) — запас ~6500 записей. Предел
молчаливый, поэтому в программе есть счётчик заполнения и предупреждение.
Упрутся — переносить на IndexedDB (в file:// работает, квота ~1 ГБ).

File System Access API (`showDirectoryPicker`) **из file:// работает** —
проверено вызовом: возвращает AbortError (нет пользователя), а не
SecurityError. На этом сделаны автокопии в выбранную папку. В Firefox
API нет — там ручная копия в папку загрузок.

## Правила работы
1. **Ничего не выдумывать.** Формы документов, расшифровки кодов, правила
   нумерации берутся только из присланных заказчиком файлов. Нет образца —
   поле оставляется пустым с подсказкой, а не заполняется догадкой.
   Предположения называть предположениями прямо.
2. **Проверять, а не полагаться.** Изменения в приложении проверяются
   безголовым Chromium (playwright лежит в `$(npm root -g)/playwright`,
   Chromium в `/opt/pw-browsers`), вёрстка — замером, а не на глаз.
   Выгрузка в Word — `scripts/проверка_docx.py`, в Excel —
   `scripts/проверка_xlsx.py` (обе ловят порядок элементов: Office не
   говорит «переставлен элемент», он объявляет файл повреждённым).
3. **Наименование организации** в документах — только нейтральное, из поля
   настроек. Никаких иных характеристик заказчика в текстах и файлах.
   Все данные в примерах — образец.
4. Ветка разработки: `claude/ndt-lab-optimization-2rpoge`.

## Что сделано и что ждёт заказчика
Сделано: журнал, справочники, пульт, обмен между местами с переносом
удалений, резервная копия, фильтры и сортировка, автоматическая нумерация
протоколов и актов (право выдачи — эстафета), акт о проведении работ по
форме заказчика с выгрузкой в Word, выгрузка разделов и всей базы в
настоящий .xlsx, автокопии в выбранную папку с поколениями и контроль
заполнения хранилища.

`.docx` и `.xlsx` собираются своим кодом (ZIP без сжатия, `zipStore`) —
библиотек нет и быть не может, программа остаётся одним файлом без сети.

Ждёт ответа заказчика:
- образец **протокола** по методу (акт есть, протокола нет);
- даты поверки приборов (заполнит сам);
- четыре вопроса по системе менеджмента — `ТЗ/Проработка_система_менеджмента.md`;
- два расхождения по акту 28-2026 — `ТЗ/Проработка_номера_протоколов.md`, раздел 5.
