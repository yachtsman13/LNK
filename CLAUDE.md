# Система ЛНК — постоянные правила проекта

## Язык
**Всё общение с заказчиком — только по-русски.** Ответы, пояснения,
сообщения об ошибках. В коде и документации проекта — тоже русский:
имена функций, переменных, комментариев уже написаны так, продолжать так же.

## Условия у заказчика (не меняются)
- Прав администратора нет. Ставить ничего нельзя, portable-программы можно.
- Сети между рабочими местами нет — обмен только файлами (флешка, общая папка).
- Office 2016, AutoCAD, Acrobat. Windows 11.
- Рабочих мест 3, в перспективе 6.

## Как устроена программа
`Приложение/ЛНК.html` — один самодостаточный файл, открывается с диска или
флешки, без установки и без сети. Собирается скриптом:

    python3 scripts/export_json.py   # данные из Excel → Приложение/данные.json
    python3 scripts/export_ppr.py    # план-график ППР  → Приложение/ппр.json
    python3 scripts/export_pg.py     # планы-графики    → Приложение/планы.json
    python3 scripts/build_app.py     # исходник+данные  → Приложение/ЛНК.html

**Править только части в `Приложение/исходник/`**, потом пересобирать.
Исходник разбит на части: `стили.css`, `страница/*.html` и
`код/NN_*.js` по разделам. Порядок склейки — `исходник/порядок.txt`;
части склеиваются как есть, без разделителей. Новый файл — обязательно
строкой в `порядок.txt`. `ЛНК.html` — сборка, руками не трогать.

**Номер версии поднимать при каждой выдаче файла заказчику.** Номер лежит
литералом в `scripts/export_json.py` (`"версия": "X.Y"`), оттуда попадает
в `Приложение/данные.json` и показывается в шапке (`DB.версия`) вместе
с датой сборки (`DB.собрано`). Менять ОБА: править литерал и заново
гонять `export_json.py`, либо править прямо в `данные.json`.

Поднимать версию безопасно: номер попадает в сохранённые записи только
как штамп (`baseVersion` у журнала, `версия` у справочников), а
`loadJournal`/`loadReg` читают `rows` независимо от него. Ключи хранения
версии не содержат — данные заказчика от смены номера не теряются.

## Хранение данных
Данные живут в IndexedDB (база `lnk_data`, хранилище `kv`, ключ → строка,
те же ключи `lnk_*`, что были в localStorage). Ключи **без номера версии**
— иначе новая версия программы откроется пустой.

**ХР** (`исходник/код/00_хранилище.js`) — обёртка над IndexedDB, те же
методы `getItem/setItem` как над картой в памяти. При запуске вся база
читается из IndexedDB в память, и только потом стартует основной код.
Запись — в память сразу и в IndexedDB следом; `ХР.дождаться()` ждёт,
пока записи дойдут. В коде вместо `localStorage.` — только `ХР.`.

Квота IndexedDB из file:// — сотни МБ и больше. File System Access API
(`showDirectoryPicker`) **из file:// работает** — на этом сделаны автокопии.
В Firefox API нет — там ручная копия в папку загрузок.

## Безопасность
- Подпись пакетов обмена, резервных копий и переезда — **ECDSA P-256 + SHA-256**.
- У каждого рабочего места свой ключ; закрытый ключ — только в хранилище браузера.
- Первый открытый ключ подтверждается после сверки отпечатка.
- Пять ошибок пароля за 15 минут блокируют вход на 15 минут.
- Восстановление — одноразовый код, выдаёт временный пароль руководителю.
- Новые пароли — 4–128 знаков; предсказуемые значения и повторы одного знака запрещены.
- PBKDF2-SHA-256, 310000 итераций; число итераций сохраняется в записи.

## Правила работы
1. **Ничего не выдумывать.** Формы документов, расшифровки кодов, правила
   нумерации берутся только из присланных заказчиком файлов. Нет образца —
   поле оставляется пустым с подсказкой. Предположения называть предположениями.
2. **Проверять, а не полагаться.** Перед каждой выдачей:
   `python3 scripts/build_app.py && node scripts/проверка_программы.js` —
   все разделы, все выгрузки, хранилище, обмен, резервная копия.
   Новая функция — новый пункт в проверку.
   Вёрстка — `scripts/проверка_печати.py` (pymupdf): нет листа с одними
   подписями, разделы не разорваны, строки не висящие.
3. **Наименование организации** — только нейтральное, из поля настроек.
   Никаких характеристик заказчика в текстах и файлах. Данные в примерах — образец.

## Что сгенерировано своим кодом (без библиотек)
`.docx` и `.xlsx` собираются своим кодом (ZIP без сжатия, `zipStore`) —
библиотек нет и быть не может, программа остаётся одним файлом.

**.docx** — ZIP-архив с `word/document.xml`. Порядок элементов критичен:
`tabs` ПЕРЕД `spacing` в `pPr`; `tblLayout` ПОСЛЕ `tblBorders` в `tblPr`;
`vertAlign` ПОСЛЕ `sz`/`szCs` в `rPr`. Таблицы — `tblLayout fixed`.
Ширины колонок — замер canvas настоящим шрифтом (твипы).
`keepNext` + `cantSplit` на подписях, `keepLines` на разделах.
Неразрывные пробелы — `w:noBreakHyphen` в Word, `break-inside:avoid` в CSS.

**.xlsx** — ZIP-архив, парсится руками (`zipЧитать`/`zipТекст`), распаковка
DEFLATE через `DecompressionStream('deflate-raw')`. Колонки сопоставляются
по ТЕКСТУ заголовка, не по номеру. Даты — серийное число Excel (день 0 = 30.12.1899).

## Ключевые паттерны кода

### REGS — справочники
`REGS.ключ = { arr, key, view, pfx, title, name, fields }` — описание
справочника. `fields` — массив полей с типами: `text`, `area`, `select`,
`ref`, `date`, `месяцы`. `editReg()` строит форму автоматически.

### Сидированные данные
`НД_ПО_УМОЛЧАНИЮ`, `ПРАЗДНИКИ_ПО_УМОЛЧАНИЮ`, `СДАНК_ОБЪЕКТЫ` и т.д. —
подставляются через `loadReg()` при первом запуске, если ключа нет.
Ваши правки не трогают. `null` (не `[]`) отличает «ещё не трогали»
от «сохранили пустым нарочно».

### Оверлеи
Паттерн обновления уже сохранённых данных: массив после `loadReg()`,
правит только пустые поля (`только в пустое`). Пример:
`НД_КАТЕГОРИЯ_2026_09`, `ПОВЕРКА_ИЗ_ПАСПОРТА_2026_09`.

### Единый сборщик данных
`всеДанные()` — один список всего, что хранит программа.
`применитьДанные(d, заменить)` — используют ручная копия, автокопия,
файл обмена, восстановление. Добавили реестр в одном месте — он везде.

### Канонические ID
`сидId(pfx,i)` — id вычисляется из позиции в сиде, одинаков на всех местах.
`каноническиеId()` переводит уже сохранённые записи на канонические id.

### Типы полей
- `podr` — выпадающий список из справочника подразделений
- `ref` — ссылка на карточку того же справочника (исключает текущую запись)
- `месяцы` — список select на каждый год
- `допуск:1` — поле-допуск, рисуется в отдельном блоке `блокДопусков()`

### Статусы сроков
`срокЛаб()` — bad/warn/ok паттерн для всех периодических требований
(поверка, аттестация, инструктаж, ПБ, ОЗП, электробезопасность, пожбез).

### Производные задачи
`производныеЗадачи()` — вычисляются из ППР, поверки, сроков лаборатории,
инструктажа. Не хранятся, а вычисляются. Попадают в «Задачи» и на пульт.

## Глобальные переменные
`_папкаДок` — выбранная папка с документами (корень флешки).
`_место` — код рабочего места (0-9).
`_подпись` — объект подписи (ключ, отпечаток, доверенные).
`DB` — данные из `данные.json` (версия, собрано).
