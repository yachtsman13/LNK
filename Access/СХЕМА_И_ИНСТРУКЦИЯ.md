# ЛНК в Access — схема, данные, код, сборка

## Важное техническое ограничение — сразу, честно

Я работаю в Linux-песочнице без Windows и без самого Access — файл `.accdb` (тем более
с формами и VBA) физически негде собрать и открыть, чтобы проверить. Формы и отчёты
Access — это закрытый двоичный формат, который умеет писать только сам Access.

Поэтому в этой части я отдаю не готовый файл базы, а всё остальное — то, что реально
можно подготовить и что вы за 30-40 минут собираете в Access сами по этой инструкции
(это стандартный Import Wizard, кликать, а не программировать):

- продуманную схему таблиц и связей;
- данные, готовые к импорту (CSV — Access импортирует их в новые таблицы сам);
- код VBA (тот же язык, что и в Excel-макросах) — импортируется так же, через Alt+F11;
- точные шаги по созданию форм и кнопок.

Если хотите, могу пройти этот процесс с вами по шагам в следующих сообщениях, когда вы
будете за компьютером с Access — так надёжнее, чем полагаться на письменную инструкцию.

## Зачем вообще Access, а не только Excel

Три конкретные вещи, которые Access решает лучше, чем Excel + мои VBA-костыли:

1. **Одновременная работа 3 человек по сети.** В Excel второй пользователь при открытии
   занятого файла получает «только для чтения» — весь наш разговор про блокировки и
   атомарную запись был попыткой обойти это средствами VBA. В Access несколько человек
   могут одновременно редактировать РАЗНЫЕ записи одной таблицы «из коробки» — это
   встроенный механизм блокировки на уровне записи, а не файла целиком.
2. **Целостность данных.** Специалист привязан к записи по ID, а не по тексту ФИО —
   опечатка в имени не потеряется незаметно, как может случиться в Excel с ВПР/ИНДЕКС.
   У специалиста может быть несколько аттестаций (по разным методам) без дублирования
   всей строки, как приходилось делать в Excel.
3. **Безопасная нумерация.** `СледующийНомерВСерии` в `modAccessConfig.bas` читает
   максимум прямо из таблицы в момент нажатия кнопки, а не из статичной формулы
   COUNTIFS, которая в Excel не видит несохранённые правки другого пользователя.

Excel v2 никуда не девается — Дашборд и Меню остаются как быстрый, привычный способ
посмотреть картину целиком (см. раздел «Excel поверх Access» ниже).

| Поле | Тип |
|---|---|

| Год | Число (целое) |
| НомерВСерии | Число (целое) — заполняется макросом через `СледующийНомерВСерии`, не формулой |
| ДатаРегистрации | Дата/время |
| Заказчик | Короткий текст (150) |
| Объект | Длинный текст |
| Исполнитель | Короткий текст (100) |
| АрхивИнфо | Короткий текст (150) |
| ИсходящийИнфо | Короткий текст (150) |
| Отправитель | Короткий текст (100) |
| ОригНомер | Короткий текст (20) — для сверки с мигрированными данными |
| ДокументСформирован | Дата/время — проставляет макрос |
| Примечание | Длинный текст |

`РегистрационныйНомер` не храним отдельным полем — это вычисляемое значение
`=[НомерВСерии] & "-" & [Год] & "-" & [Метод]`, задайте его как **вычисляемое поле**
при создании таблицы (тип «Вычисляемое», результат — короткий текст) — тогда оно
всегда актуально и не может разойтись с исходными данными.

### Связи (схема данных)
- tblАттестации.Метод → tblМетоды.Код (один-ко-многим)
- tblЖурнал.Метод → tblМетоды.Код (один-ко-многим)

Заводить связи по ФИО не стал намеренно — в мигрированных данных встречаются
разные написания одного и того же человека («А.В. Матяш» / «Матяш А.В.»), при
жёсткой связи часть строк потерялась бы при импорте. Почистить и связать по ID
специалиста — хорошая задача на потом, когда данные приведёте к одному виду.

## Сборка: пошагово

1. **Access → Создать → Пустая база данных** — назовите `ЛНК.accdb`, сохраните в папку,
   рядом с которой лежат (или будут скопированы) папки `Шаблоны` и `Готовые` — так же,
   как в Excel-версии.
2. Для каждой таблицы: **Внешние данные → Импорт → Файл CSV** → выбрать файл из
   `Импорт_CSV/` → «Импортировать данные источника в новую таблицу» → на шаге выбора
   полей проставьте типы по таблице выше → назначьте первичный ключ (для всех, кроме
   tblМетоды — там ключ «Код», выбрать эту колонку вручную и снять авто-счётчик).
3. **Работа с базой данных → Схема данных** — перетащите tblМетоды.Код на
   tblЖурнал.Метод и на tblАттестации.Метод, включите «Обеспечение целостности данных».
4. Alt+F11 → правой кнопкой по проекту → **Import File** → по очереди `modAccessConfig.bas`,
   `modAccessChecks.bas`, `modAccessGenerate.bas`.
5. **Создать → Конструктор форм** — форма `Форма_Журнал`, источник записей — tblЖурнал,
   поля на форме: Метод (раскрывающийся список из tblМетоды), Год, НомерВСерии,
   Заказчик, Объект, Исполнитель, ДатаРегистрации, ДокументСформирован (сделать
   недоступным для ввода — заполняется только макросом). Добавьте кнопку «Сформировать
   документ» → на событие `На нажатие кнопки` впишите:
   ```vba
   Call СформироватьДокумент(Me)
   ```
6. Аналогично сделайте простые формы для tblСпециалисты+tblАттестации (можно как
   форма с подчинённой формой — один специалист сверху, его аттестации снизу),
   tblСИ, tblНД, tblИнструктажи, tblЗадачи — обычные табличные формы, без кнопок,
   для удобного ввода вместо голой таблицы.
7. **Кнопка нового номера**: на форме Журнала, в событие формы `После вставки` (или на
   кнопку «Новая запись») впишите:
   ```vba
   Me!НомерВСерии = СледующийНомерВСерии(Me!Метод, Me!Год)
   ```
   (нужно, чтобы поле «Метод» и «Год» были уже заполнены до вызова).

## Работа по сети на 3 ПК (решает то, что обсуждали для Excel)

Стандартная и надёжная схема — **разделить базу на «back-end» и «front-end»**:

1. Собранный `ЛНК.accdb` (с таблицами и данными) переименуйте в `ЛНК_данные.accdb` и
   положите в общую сетевую папку.
2. Средства базы данных → **Разделение базы данных** — Access сам создаст
   `ЛНК_front.accdb` с формами/кнопками/макросами и подключит к нему таблицы из
   сетевого файла по ссылке.
3. `ЛНК_front.accdb` скопируйте **на каждый из 3 ПК локально** (не в сетевую папку) —
   так формы работают быстро, а данные всё равно общие. При обновлении форм/макросов
   пересобираете front-end и раздаёте копию заново — сами данные не трогаются.

Это ровно то разделение «код локально / данные в сети», которое мы обсуждали для
Excel — только Access делает синхронизацию данных сам, без атомарной записи и
файлов-блокировок, которые пришлось бы городить вручную.

## Excel поверх Access — «быстрый анализ» без потери Дашборда/Меню

В `ЛНК_Реестры_v2.xlsx` можно подключить листы напрямую к данным Access, чтобы не
вести два независимых места правды:

**Данные → Получить данные → Из базы данных → Из базы данных Microsoft Access** →
указать `ЛНК_данные.accdb` → выбрать нужные таблицы → «Загрузить в... → Таблица» на
новый лист. У такого подключения есть кнопка **Обновить все** (и её можно поставить
на автообновление при открытии файла: Данные → Свойства подключения → «Обновлять при
открытии файла») — Дашборд и Меню продолжают питаться от этих таблиц теми же формулами
COUNTIF/COUNTIFS, что и сейчас, только источник данных — Access, а не ручной ввод в
соседнем листе. Реальный ввод данных при этом идёт только в Access-формах — единая
точка правды, Excel — витрина для чтения.

## Как это ложится на процесс работы (эргономика)

То же 8-шаговое движение, что на листе «Меню» в Excel, просто шаги 3-4 теперь
выполняются через формы Access, а не строки таблицы:

1. Планирование — Форма_Задачи / Форма_ПланГрафик.
2. Подготовка — Дашборд в Excel (подключён к Access) подсвечивает просрочки заранее.
3. Контроль и ввод результатов — Форма_Журнал, новая запись, номер присваивается
   автоматически при вводе метода и года.
4. Формирование документа — кнопка на Форма_Журнал, с проверкой аттестации исполнителя.
5. Проверка и подписание — как и раньше, вручную.
6. Печать пакета — здесь пока проще остаться на модуле `modPrint.bas` из Excel-версии
   (он написан универсально для файлов из папки «Готовые», ей всё равно, кто их туда
   положил — Excel-макрос или Access-макрос).
7. Сшивание и регистрация — без изменений.
8. Архив — без изменений, `tblНД`/`tblЖурнал` дают ту же картину сроков хранения.
